# ARD JC1060P470C 통합 펌웨어 (ESP-IDF 5.5.5)

GUITION JC1060P470C (ESP32-P4 + ESP32-C6-MINI-1U, 7" 1024x600 JD9165 MIPI-DSI, GT911 터치) 한 장으로
기존 **HMI_MCU** 화면과 **ControlMCU**의 조작·음성 역할을 전환해 사용합니다.
**DriveMCU는 기존 독립 보드 그대로 유지**하며 PC와 JC1060 터치 화면에서 PC 서버를 거쳐 제어합니다.
JC1060에는 모터·센서·GPS 등 추가 보드를 연결하지 않습니다.
내장 **ES8311 마이크·스피커**로 음성을 입력하고, 기존 PC의 음성 인식·응답·안내 음성을 재생합니다.

> 초기 버전은 실물 없이 작성했습니다. 2026-10-24 V2 패널 수정과 터치 설정 UI에 대해 사용자가 정상 동작을 확인했습니다.
> 이후 원격 Wi-Fi 기록/QR 기능과 병합한 버전은 호스트 회귀 검사와 별도로 실물 재확인이 필요합니다.

## 내장 마이크·스피커 사용

1. 새 P4 펌웨어와 수정된 `ARD_MAIN`을 함께 사용한다. PC 프로그램은 다시 시작한다.
2. PC **설정 → 일반/하드웨어 → 제어 단말**에서 JC1060을 선택하고 저장한다. 음성 대상도 JC1060으로 자동 선택되며, 필요하면 별도로 ControlMCU를 선택할 수 있다.
   이미 JC1060을 선택해 둔 경우 **음성 입출력 보드**도 JC1060인지 확인하고 저장한다.
3. 보드 **Voice** 탭에서 **SPEAKER TEST**로 출력을 확인한다. **VOL - / VOL +**, 음소거, 재생 중지를 사용할 수 있다.
4. **MIC ON → PTT**를 선택하고 **HOLD TO TALK**를 누른 동안 말한 뒤 놓는다. **VAD**에서는 발화를 감지해 자동 녹음하며 약 0.75초 침묵 후 전송한다.
5. 마이크 레벨, 녹음·전송·처리·재생 상태와 오류 수를 Voice 탭에서 확인한다. 마이크 ON/OFF와 보드 볼륨은 NVS에 저장한다.

2026-10-26 소스 수정: 터치 직후 실제 마이크 설정을 읽어 현재 상태 `MIC ON/OFF`와 버튼의 다음 동작 `Turn mic on/off`를 따로 표시합니다. PC에서 음성 보드를 선택하지 않은 상태도 마이크 꺼짐과 구별합니다. 이 변경의 펌웨어 빌드·실물 검증은 아직 수행하지 않았습니다.

입력·출력은 보드 내장 마이크·스피커이며, 음성 인식·AI·TTS는 기존 PC 엔진을 사용한다. 녹음은 기본 15초, 설정상 최대 20초로 제한한다. PC 연결이 끊기거나 다른 음성 보드를 선택하면 녹음·업로드를 중단한다. 스피커 재생과 짧은 잔향 구간에는 녹음을 억제한다. 이는 소프트웨어 반향 억제이며 완전한 AEC는 아니다.

부팅 멜로디와 PC의 카메라·로봇·선별·승인·비상정지 안내를 내장 스피커로 재생한다. 화면의 구동 명령은 PC의 기존 DriveMCU API로 전달하며 PC가 안내한다.

**VAD 오동작 방지 (2026-10-25):** 소리가 200 ms 이상 이어져야 녹음을 시작하고, 말소리 구간이 합쳐서 300 ms가 안 되는 녹음은 PC로 보내지 않고 버린다(두드림·클릭 등). 조용할 때의 주변 소음 수준을 약 4초 단위로 따라가며 그 3배와 PC 감도 중 큰 값을 넘어야 말소리로 본다. 스피커 앰프가 꺼질 때의 "툭" 소리로 다시 녹음되지 않도록 앰프가 꺼진 뒤 0.6초 동안 녹음을 막는다. PTT는 사용자가 직접 누르는 것이므로 그대로다. 정책 시험: `test/test_voice_capture.c`.

**안내 음성 반복 방지·켜기/끄기 (2026-10-26):** PC의 자동 안내 음성("분류구조 작동합니다." 등)은 같은 문장이 8초 안에 다시 요청되면 말하지 않습니다. 버튼을 길게 누르거나 연달아 누르는 동안에는 처음 한 번만 나오고, 8초 동안 조작이 없어야 다시 나옵니다. 긴급 정지 사이렌은 2초에 한 번만 울립니다. **설정 → Sound → 안내 음성: 켜짐/꺼짐**으로 PC 안내 음성을 끌 수 있으며, 이 설정은 NVS(`jc_audio/guide`)에 저장되어 재부팅 후에도 유지됩니다. 보드는 하트비트(3초)마다 PC에 이 설정을 알립니다. AI 대답·음성 명령 응답과 긴급 정지 사이렌은 끄지 않습니다. JC1060이 음성 보드로 선택돼 있을 때만 적용됩니다.

**명령 구분:** `x`/`stop`은 기존 모터 비상정지이고, `audio_stop`은 소리만 중지한다. PC 음성 제어 경로의 `stop`은 JC1060에서 `audio_stop`으로 변환된다. `audio_status`, `audio_test`, `vol=0..21`, `audio_mic_on/off`, `vad`/`ptt`도 지원한다.

오디오 코덱은 `espressif/esp_codec_dev` **1.2.0**에 고정했다. 설치된 ESP-IDF **5.5.5**에서 컴파일·링크했으며, 실물 마이크·스피커 및 모터·화면 동시 운전 검증은 별도로 필요하다. 자세한 결과는 [2026-10-25 음성 이식 기록](../../results/261025_JC1060_내장음성_이식.md)에 있다.

## 터치 조작

JC1060은 터치 화면으로 DriveMCU와 로봇 명령을 PC에 전달합니다.
게임패드 페어링·입력·BLE 검색 코드는 제거했고 P4의 Bluetooth도 비활성화했습니다.
화면의 E-STOP과 RE-ARM은 일반 명령 대기열과 독립적인 경로를 사용합니다.

2026-10-26 화면 배치 수정: 1024×600 화면에서 상단 상태바 72px와 탭 버튼 56px를 제외하고,
각 일반 탭을 여백 포함 472px 높이에 맞췄습니다. 탭·패널의 상하 스크롤과 밀어서 탭 전환을
차단하며 탭 버튼으로 이동합니다. 조이스틱을 놓아도 스크롤을 다시 켜지 않습니다.
카메라는 616×392px 표시 영역에 이미지 전체를 비율대로 맞추고 상태 문구를 별도 줄에 표시합니다.
Wi-Fi 검색 결과는 4개씩 표시하고 이전·다음 버튼으로 선택합니다. 설정 입력칸은 가로 입력 이동만 허용합니다.
이 화면 변경도 빌드·업로드 및 실물 확인은 아직 수행하지 않았습니다.

- Drive 탭은 **연속 제어** 화면으로 시작하며, 조이스틱이나 레일 버튼을 누르면 바로 재가동해 움직입니다(2026-10-26, RE-ARM 불필요). 모드 버튼으로 **단일 스텝**과 전환합니다. 왼쪽에 상태·전원·설정을 모으고 오른쪽 조이스틱을 지름 **360px**로 키웠습니다(이전 208px).
- 연속 제어에서는 원형 조이스틱을 누르는 즉시 자동으로 재가동하고 움직입니다. E-STOP 후에도 다시 누르면 재가동합니다. 재가동이 거부되면(이동 큐·귀환 동작 중) 1초마다 다시 시도합니다. 위·아래는 디스크 전진·후진, 좌·우는 회전이며 대각선은 두 동작을 합칩니다. 레일은 `Rail + / Rail -`를 누르는 동안 움직입니다.
- 조이스틱 중앙의 원은 **데드존**입니다. 기본 반경은 이동 범위의 **20%**, 조절 범위는 **5~30%**이며 안에서는 디스크 명령을 보내지 않습니다. 밖에서는 남은 이동 거리를 0~1로 정규화한 뒤 제곱해 명령 빈도를 높입니다. 기본 데드존에서 반경 60%의 입력은 최대 빈도의 25%, 끝은 100%에 해당합니다.
- 2026-10-26부터 연속 제어는 **속도 조그**입니다. 조이스틱 값은 100ms마다 PC를 거쳐 DriveMCU의 `j<x>,<y>,<z>` 명령(각 축 최대 속도의 -1000~1000‰)으로 전달되고, DriveMCU가 자체 가감속으로 속도를 바꿉니다. 이전의 "20스텝 이동 → 정지 → 다음 20스텝" 방식은 매번 가속·정지를 반복해 실효 속도가 약 40~50 step/s에 그쳤고 끊겨 보였습니다.
- **최대 속도** 슬라이더(10~100%, 기본 100%)는 조이스틱 끝까지 밀었을 때의 속도입니다. 100%는 DriveMCU 최대 속도 설정(`mxs`/`mys`, 기본 500 step/s)과 같으며 그보다 빨라지지 않습니다. Y축 탈조를 막으려고 낮춘 500 step/s 제한을 그대로 따릅니다.
- 손을 떼면 `j0,0,0`으로 **감속 정지**합니다(기본 가속도 500 step/s²에서 최고 속도로부터 약 1초·250스텝). 정지가 너무 길면 `mxa`/`mya`로 가속도를 올려 시험합니다. E-STOP은 기존처럼 즉시 정지·드라이버 해제입니다.
- DriveMCU는 조그 명령이 **400ms** 동안 오지 않으면 스스로 감속 정지합니다(데드맨). Wi-Fi가 끊겨도 계속 움직이지 않습니다.
- Drive 탭 위치 추정은 조그 중 0.5초마다, 손을 뗀 뒤 1.5초에 DriveMCU가 보고한 실제 스텝 수로 갱신합니다.
- 이전 DriveMCU 펌웨어(상태에 `jogging`이 없음)에서는 PC가 기존 20스텝 방식으로 자동 전환합니다. 이때 최대 속도 %는 기존 명령 간격으로 환산됩니다.
- 단일 스텝은 **단위 이동량 1~2000스텝**, 기본 50스텝입니다. `-1/+1`(길게 누르면 반복) 또는 `1/10/50/100/500/1000/2000` 빠른 선택으로 바꿉니다. 디스크 전후·회전, X·Y, PID를 끈 레일에 같은 단위를 적용합니다. PID 레일은 기존처럼 145~175mm 목표를 5mm씩 조정합니다. 이 화면의 조작 설정은 재부팅 시 기본값으로 시작합니다.
- 손을 떼면 새 명령을 중단합니다. 터치 갱신이 250ms 끊겨도 중단하며, 탭·모드 전환이나 통신 단절에서는 수동 제어를 해제합니다. 다시 누르면 자동으로 재가동합니다.
- PC는 명령을 하나만 전송 대기시키고 300ms가 지난 미전송 명령을 폐기합니다. DriveMCU에서 다른 이동 명령·귀환·자동 선별이 동작하거나 재부팅이 감지되면 조그를 보내지 않습니다. 레일 PID와는 무관하게 디스크 조그가 동작하며, **레일 연속 조작을 시작하면 DriveMCU가 PID를 자동으로 끕니다**(상태 `pid:false`). 조그 중 상태는 0.5초마다 확인합니다.
- 수동 제어 해제는 자동 선별 취소와 구분합니다. **E-STOP**은 기존처럼 구동과 자동 선별을 중단합니다.

비선형 조이스틱 제어를 사용하려면 새 `joystick` 요청을 처리하는 수정된 PC 프로그램도 다시 시작해야 합니다. 기존 `input/pulse` 요청은 호환됩니다. 이번 구동 탭 개편은 2026-10-26 소스에 반영했으며 펌웨어 빌드·업로드와 실제 터치 확인은 사용자가 수행해야 합니다.

## 시계 동기화

Wi-Fi에서 IP를 받으면 SNTP 동기화를 시작합니다. 인터넷 시간 서버에 접근할 수 없어도 수정된 PC 서버의 HMI 응답에 포함된 UTC 시간을 받아 보정합니다. 화면은 한국 시간(UTC+9)으로 표시하며, 아직 유효한 시간이 없으면 `동기화`를 표시합니다. PC 보정 경로를 쓰려면 PC 프로그램을 다시 시작해야 합니다.

## 기존 대비 개선점

- HMI·조작·음성을 JC1060 내장 기능으로 통합하고 기존 DriveMCU는 보존합니다.

## 화면 출력 방식 (2026-10-25)

부팅 색상 막대·흰색/검은색 진단과 `Use synchronous full-frame UI redraw` 옵션은 제거했습니다.
남아 있던 로컬 `sdkconfig`가 진단 옵션을 다시 켜는 일이 없도록 코드와 메뉴 항목을 모두 삭제했습니다.

LVGL은 DPI 프레임버퍼 2개(각 1,228,800 bytes, PSRAM)에 매 프레임 전체 화면을 직접 그립니다.
표시 중이 아닌 버퍼에 그린 뒤 캐시를 기록하고, 다음 프레임 시작에 버퍼를 교체합니다.
교체가 끝난 것(프레임 완료 인터럽트)을 확인한 뒤에야 LVGL이 이전 버퍼에 다시 그립니다.
표시 중인 버퍼에 CPU로 1.2 MB를 복사하던 이전 방식보다 PSRAM 사용량이 줄고, 찢어짐과
부분 갱신 화면이 생기지 않습니다. 시리얼에 `underrun happens`가 보이면 PSRAM 대역폭 부족,
`LCD frame swap timeout`이 보이면 DSI 프레임 완료 인터럽트 문제를 의심합니다.
프레임버퍼가 정상인데도 사라지지 않는 흐린 잔상은 패널 자체의 화상 잔류일 수 있으므로
화면을 몇 분 꺼 두었다가 다시 확인해 구분합니다.

## Wi-Fi DHCP 진단 (2026-10-26)

`ARD_WIFI_DIAGNOSTICS`를 켜면 `WIFI_DEBUG` 태그로 5초마다 STA의 DHCP 상태,
IP·게이트웨이·넷마스크, 송수신 패킷 수와 오류 수를 기록합니다. DHCP 패킷은
DISCOVER/OFFER/REQUEST/ACK/NAK 종류와 transaction ID만 기록하며 비밀번호나
패킷 내용은 출력하지 않습니다. UART0 콘솔의 `wifi_debug` 명령으로 즉시 상태를
출력할 수 있습니다. 진단 후에는 menuconfig에서 이 옵션을 끌 수 있습니다.

수동 연결은 무선 연결에 최대 25초, 무선 연결 이후 DHCP에 최대 30초를 줍니다.
반복 연결로 무한히 기다리지 않도록 전체 상한은 90초입니다. IP를 받기 전에는
성공한 Wi-Fi 설정이나 연결 이력을 덮어쓰지 않습니다.

자동 연결에서 호스트 MAC이 모두 0인 상태가 관찰돼, DHCP 시작 직전에 실제
C6 STA MAC과 호스트 인터페이스 MAC을 확인·보정합니다. `WIFI_MAC` 로그로
두 주소와 보정 결과를 확인할 수 있습니다. 동작 중인 인터페이스의 주소와
무선 장치 자체의 주소는 바꾸지 않습니다.

- `dhcpc=1`인데 DHCP TX가 0이면 P4의 DHCP 시작·송신 경로를 확인합니다.
- DHCP TX 오류가 있으면 Wi-Fi 드라이버·C6 전송 경로를 확인합니다.
- DHCP TX는 성공하지만 RX가 없으면 C6·SDIO·AP의 응답 전달 경로를 확인합니다.
- OFFER/ACK를 받았는데 IP가 없으면 TX/RX transaction ID와 수신 오류를 비교합니다.

패킷 수는 부팅 이후 누적입니다. 다른 시도와 비교할 때는 직전 값과의 차이를
확인합니다. 송신 API 성공은 AP가 패킷을 받았다는 보장이 아닙니다.

```powershell
python test/run_wifi_debug.py
python test/run_wifi_join_deadline_tests.py

```

이 검사는 C 코드를 컴파일하므로 사용자만 실행합니다. 실제 코드의 패킷 판별·드라이버 위임·대기 제한을 확인합니다.

## SD 음성과 코어 배치

현재 기본 음성은 Google Cloud `Chirp3-HD-Aoede`의 한국어·영어 28종이다.
`tools/generate_cloud_visitor_voice.py`로 생성하고, `tools/verify_visitor_voice.py`로 검사한다.
키는 PC의 지정된 비공개 설정에서 읽으며 펌웨어·SD 음성 패키지에는 넣지 않는다.
Azure SunHi / Hyunsu 및 Google Kore의 참여 안내 비교본은
`output/JC1060_Cloud_TTS_SD_20261027.zip`의 `comparison` 폴더에 있다.

웹 전송은 `python tools/upload_visitor_voice.py --host 192.168.0.30`으로 실행한다.
기기는 `/api/voice/status`와 `/api/voice/file`을 제공해야 한다. 도구는 보드의 요청 토큰을 받아
28개 WAV를 업로드하고 저장 후 SD에서 다시 계산한 SHA-256을 비교한다.
지정된 언어·안내 이름만 허용하며 임시 파일 검증 후 교체한다. 기존 파일은 `.bak`으로 보존한다.
FAT 긴 파일명 지원은 heap 방식으로 켠다. NVS와 SD를 초기화하지 않는다.

- `sdcard/ard`를 SD카드 루트로 복사한다. 한국어·영어 14종씩 총 28개 파일이며, 자세한 배치는 `sdcard/README.md`와 `sdcard/voice_manifest.json`에 있다. WAV를 플래시에 임베드하지 않는다.
- SDMMC 슬롯 0(CLK43, CMD44, D0..3=39..42, LDO4)을 10 MHz로 사용한다. C6는 기존 SDIO 슬롯 1과 핀을 유지한다. SD 마운트 실패 시 포맷하지 않는다.
- HP0: 통신, 수동구동 요청 전송, SD/파일 읽기, 설정 저장, 진단. HP1: LVGL(우선순위4), I2S 오디오(6). LP: 1초 타이머로 UI/오디오 진행 감시 후 WFI 대기. LP는 HP FreeRTOS 스케줄러의 세 번째 코어가 아니다.
- SD 작업자가 음성을 최대 512 KiB씩 PSRAM 2슬롯에 캐시한다(최대 1 MiB). 확보 실패 시 SD에서 1 KiB씩 읽어 오디오 큐에 공급한다. LVGL/I2S 태스크는 파일을 읽지 않는다. SD/PSRAM 장애가 실제로 발생했을 때의 지연·동시사용은 장치에서 확인해야 한다.
- PC 음성 답변·녹음 중에는 일반 로컬 안내를 건너뛴다. 비상정지 음성은 우선 처리하되, 정지 명령은 음성 파일을 기다리지 않고 즉시 기존 제어 경로로 보낸다.
- `scheduler_status`를 시리얼 콘솔에 입력하면 다음 진단 주기(약 1초 이내)에 CPU 구간 사용률, UI·오디오 최대 처리 간격, LP 카운터·정지 비트, 스택 여유·메모리를 출력한다. SD 상태와 캐시·큐 공급 건수도 출력한다. 자동 출력은 30초 주기이며 첫 CPU 출력은 기준 샘플이다.
- 런타임 통계는 32-bit ESP Timer의 구간 차이로 계산한다. 스택 카나리와 양쪽 idle watchdog을 유지한다. LP 감시는 오류를 알리며 자동 재부팅·구동 명령을 수행하지 않는다.
- `sdkconfig.defaults`와 로컬 `sdkconfig`에 ULP LP(8 KiB 예약), FreeRTOS 런타임 통계를 추가했다. 새 HP/LP 소스의 컴파일과 실제 스케줄링·재생 검증은 사용자 빌드 및 장치 로그가 필요하다.
  2026-10-27에는 사용자가 직접 빌드·업로드를 별도로 허용하여 실제 빌드/장치 검증을 진행했다.
  결과는 저장소 `results/261027_JC1060_빌드수정_펌웨어_SD업로드.md`를 따른다.
