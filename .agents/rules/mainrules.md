#최우선으로 지켜야할 규칙
- 사용자에게 답변은 한국어로 답한다

# File Organization Rule
- 모든 분석 결과 보고서는 `results/` 폴더 내에 생성
- 파일명은 반드시 `[날짜]_[보고서종류].md` 형식을 사용해야 함 (예: 260126_매출분석.md)
- 생성된 파일의 최상단에는 항상 작성일과 작성자를 명시

# Markdown Syntax (마크다운 문법)
마크다운 문서를 작성할 때 반드시 아래의 규칙을 따른다.
- 글머리 기호를 작성할 때에는 단일 **하이픈(-)** 과 공백을 사용한다.
- 각 헤더(Header) 뒤에는 **빈 행을 두지 않고** 바로 본문 내용을 작성한다.

#모듈화 구조
코드길이가 너무 길어져선 안된다. 각 요소 및 기능별로 구별하여 각각의 파일로 분할하여 작업한다

#펌웨어개발시 규칙
vscode와 PlatformIO를 사용하는 전제로 개발한다. 디버깅이 쉽게 시리얼 메세지를 적극활용 하여 오류메세지를 세분화한다. 대문자 소문자 구분을 철저히 지킨다. 프로젝트내 비슷한 용도의 로직이 있을때 변수와 함수는 통일하여 개발한다.
