# 로그 창 높이 조절 및 JC1060 구동 경로 정리 — 2026-10-25

## 하단 로그 창

로그 창 **아래쪽 손잡이**를 위아래로 끌어 높이를 조절한다. 마우스·터치·펜의 Pointer Events를 사용하며 드래그가 창 밖으로 나가도 종료를 처리한다. 두 번 클릭하면 기본 높이로 돌아간다.

조절한 높이는 브라우저의 `ard.logPanelHeight`에 저장하고 새로고침 때 복원한다. 최소 130px, 최대 화면 높이의 75%(상한 800px)로 제한한다. 화면이 작아지면 표시 높이만 제한하며 저장한 선호 높이는 유지한다. 키보드로 손잡이에 초점을 맞추면 ↑/↓, Shift+↑/↓, Home/End로 조절할 수 있다.

데스크톱에서는 하단 행 전체 높이를 함께 바꾸고, 모바일에서는 로그 창 높이를 바꾼다. 로그는 창 안에서 스크롤하며 기존 새로고침·삭제 버튼을 유지한다. 메인 프로그램 재시작 후 Ctrl+F5로 새 화면을 불러온다.

## 기존 DriveMCU 유지

JC1060 전환 시 DriveMCU의 IP, 연결 상태, 구동 설정, 명령 상태를 JC1060으로 바꾸거나 초기화하지 않는다. DriveMCU는 독립 네트워크 보드이며 **PC와 JC1060이 PC 서버를 거쳐 같은 DriveMCU를 제어**한다.

JC1060 펌웨어에서는 로컬 모터·외부 센서·GPS·부저 초기화와 `source=DriveMCU` 보고를 제거했다. 해당 참고 소스들은 남겨 두되 빌드에서 제외한다. 내장 화면·터치·ES8311 음성·C6 네트워크·BLE는 사용한다. 기존 DriveMCU 펌웨어 프로토콜을 변경하지 않았다.

화면 명령은 기존 `/api/drivemcu/command`로 전달한다. 게임패드는 `/api/jc1060/drive`에 최신 입력만 전달하고 축당 최대 20스텝의 기존 상대 이동 명령으로 바꾼다. DriveMCU 실제 `status.busy`를 확인하여 이전 이동 중 추가 이동을 쌓지 않는다. 전송 중 입력은 한 묶음만 유지하며 아직 보내지 않은 명령은 300ms 뒤 무효화한다.

PC 수동·음성·AI 명령, 선별 시작, 보드 구성 변경은 게임패드 조작을 해제한다. 게임패드 연결 상실·통신 실패·DriveMCU 재부팅 뒤에는 START/RE-ARM이 필요하다. PID 모드의 조그는 거부한다. 비상정지 요청은 일반 명령 큐가 가득 차도 별도 입력 경로로 전달한다.

네트워크 상실 시 이미 DriveMCU가 수락한 유한 이동은 완료될 수 있다. 이 경로는 통신 단절 상황의 즉시 물리 정지를 보장하지 않는다. 화면 위치는 PC의 수락 명령 기준 추정 스텝으로 표시하며 실제 엔코더 측정값이 아니다.
