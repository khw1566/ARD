# JC1060 내장 음성 입력 및 기존 음성 안내 이식

2026-10-25 / `ARD_MAIN` + `ARD_ESP-IDF/JC1060P470C`

## 결과와 사용 순서

JC1060의 ES8311 내장 마이크로 발화를 녹음하고, 기존 PC 음성 인식·AI·TTS를 거쳐 보드 스피커로 답변과 안내를 재생하도록 연결했다. PC 마이크 없이 보드에서 말할 수 있다. 오프라인 음성 인식 모델을 보드에 넣은 구성은 아니다.

1. 새 JC1060 P4 펌웨어를 올리고 메인프로그램 서버를 다시 시작한다. 기존에 동작하던 C6 ESP-Hosted 펌웨어를 그대로 사용한다.
2. **설정 → 일반/하드웨어 → 제어 단말 → JC1060**을 선택하고 저장한다. 음성 대상도 JC1060으로 자동 선택된다. 구형 단말과 기존 ControlMCU 음성으로 되돌릴 수 있다.
   이미 JC1060을 사용하던 설정이면 **음성 입출력 보드 → JC1060**도 확인하고 저장한다.
3. 보드 **Voice → SPEAKER TEST**로 스피커와 볼륨을 확인한다.
4. **MIC ON → PTT**를 선택한다. **HOLD TO TALK** 또는 게임패드 **RT**를 누른 동안 말하고 놓으면 PC로 전송한다.
5. **VAD**에서는 발화가 시작되면 자동 녹음하고 약 0.75초 침묵 후 전송한다. 기본 최대 녹음 길이는 15초다.
6. Voice 탭의 입력 레벨·녹음/업로드/처리/재생 상태·전송 성공/오류 수로 동작을 확인한다. 입력 임계값은 기존 PC 음성 감도 설정을 사용한다.

## 구현 범위

| 영역 | 처리 |
|---|---|
| 마이크 | ES8311 ADC, I2S 16 kHz/16-bit, 왼쪽 마이크 슬롯 기본값. VAD/PTT 및 로컬 마이크 ON/OFF |
| 입력 전송 | PCM16LE 모노 발화를 `/api/jc1060/voice`로 전송. 보드에 기본 480,000바이트 PSRAM 버퍼 한 개. 발화 길이 최대 20초 |
| PC 처리 | 기존 `process_voice_command`의 Whisper/OpenAI STT·AI·TTS 재사용. JC1060 음성 작업자 한 개, 중복 요청은 busy 응답 |
| 출력 | 기존 UDP 5005 / 16 kHz 모노 PCM을 ES8311 스피커로 재생. TTS·음성 안내·기존 미디어 경로 유지 |
| 볼륨 | 기존 0~21 범위, 음소거·재생 중지. JC1060에서는 보드가 볼륨을 적용해 PC와 보드의 중복 감쇠 방지. 구형 경로의 PC 볼륨 처리는 유지 |
| 저장 | 마이크 활성 상태·보드 볼륨은 NVS, PC VAD/PTT·감도는 기존 로컬 `.env` 경로로 저장 |
| 안내 | 기존 PC 연결/해제·카메라·로봇·선별·승인 안내와 비상정지 사이렌/TTS가 선택한 음성 보드로 출력. 로컬 터치·게임패드 동작은 별도 고정 안내 큐로 연결 |
| 부팅 | 기존 ControlMCU의 6음 부팅 멜로디를 내장 스피커에서도 재생 |

스피커 재생과 0.5초 잔향 구간, PC 처리 중, 업로드 중, 연결 끊김, 다른 보드 선택 시 마이크 발화 캡처를 억제한다. 완전한 전이중 AEC를 구현한 것은 아니며, 실제 설치 환경의 반향과 감도 조정은 확인해야 한다. MIC OFF는 녹음·업로드를 끈다.

모터 프로토콜의 `stop`/`x`는 그대로 비상정지다. 음성만 멈출 때는 `audio_stop`을 사용하며 PC의 음성 명령 경로에서 자동 변환한다. **STOP AUDIO**는 모터를 정지시키지 않는다. 모터 TCP 명령을 PC가 이미 안내한 경우 JC1060이 같은 안내를 다시 요청하지 않는다.

## 자원과 배선

- I2C SDA/SCL: GPIO 7/8, ES8311 주소: 7-bit `0x18` (코덱 드라이버 표기는 8-bit `0x30`).
- I2S MCLK/BCLK/LRCK/DOUT/DIN: GPIO **13/12/10/9/48**, 스피커 앰프 enable: GPIO **11**.
- 입력 슬롯·마이크 게인·최대 녹음 길이·I2S 핀은 Kconfig에서 변경한다. 코덱은 `espressif/esp_codec_dev` 1.2.0을 사용한다.
- 음성 태스크는 core 0에서 실행한다. 기존 core 1 모터 플래너·스텝 ISR 구성을 유지했다. I/O 작업자에 태스크 watchdog을 적용하고 건강 로그에 음성 태스크 stack 여유를 추가했다.
- 기본 발화 버퍼는 **480,000바이트 PSRAM**. PCM 큐는 16개 고정 패킷, 태스크 stack 합계는 **16,384바이트**다. 최대 설정 20초에서는 발화 버퍼가 640,000바이트다. I2S TX/RX DMA 버퍼는 약 8KiB이고 큐·RTOS·DMA 객체 관리 오버헤드는 별도다.
- 전체 펌웨어 map 기준 DIRAM 사용량은 **148,744바이트**, 남은 DIRAM은 **427,720바이트**다. 이는 정적 링크 집계이며 런타임 heap·stack 사용량 측정이 아니다.

배선은 [Espressif 저장소의 JC1060 보드 기여 PR](https://github.com/espressif/esp-claw/pull/51/files)과 로컬 동종 보드 설정을 교차 확인했다. I2S 구성은 [ESP-IDF 공식 문서](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32p4/api-reference/peripherals/i2s.html)를 참고하고 실제 설치된 5.5.5 헤더와 컴파일러로 검증했다. 보드 리비전의 물리 배선과 소리는 실물 검증 대상이다.

## 검증 및 산출물

- ESP-IDF **5.5.5**, ESP32-P4, 기존 RISC-V 툴체인으로 **전체 컴파일·링크 성공**. 기존 사용 가능한 빌드 폴더를 보존하고 `tmp/jc1060-voice-20261025/firmware-build`에서 빌드했다.
- LCD V2·동기 전체 화면 갱신·C6 SDIO **10MHz** 설정이 기존 값과 같음을 확인했다.
- 당시 이미지 보존본: `tmp/jc1060-voice-20261025/voice-build-preserved/ard_jc1060p470c.bin`, **1,859,072바이트**, 6MiB 앱 파티션 약 **70% 여유**.
- SHA-256: `82f31e7b3e21c3a6113169bb94df58c0544be17c173256dd2ab3030ec483f723`.
- 설치된 ESP32-P4 컴파일러로 변경 C++ 소스 7개 문법 검사 통과. 새 오디오 코드에 대한 경고는 없었고, 전체 빌드에는 기존 공유 Wi-Fi 구조체 초기화 경고 3개가 있었다.
- 실제 `voice_capture.h`를 사용하는 네이티브 C 검사에서 VAD 발화/침묵, PTT 시작/해제, 입력 억제 시 취소, 최대 길이, 해제 전 재시작 방지 정책을 확인했다.
- PC Python **59개**, JavaScript **3개 검사 묶음**, 실제 브라우저 설정·전환 **8개 항목**을 통과했고 브라우저 JavaScript 예외는 0개였다. 결과는 같은 폴더의 `verification.json`에 보관한다. 브라우저는 실물 MCU와 분리한 템플릿/정적 파일/설정 API 테스트 환경이다.
- **업로드, 실물 녹음·스피커 음량, 실제 STT/TTS 왕복, 장시간 재생, 화면·모터·음성 동시 부하 검증은 수행하지 않았다.**

보통처럼 JC1060 프로젝트의 `build.ps1`로 빌드·업로드할 수 있다. ESP-IDF를 직접 사용할 때는 먼저 정식 `export.ps1`를 실행해야 한다. `IDF_PATH`만 수동 지정하면 ESP-Hosted Kconfig에 필요한 `ESP_IDF_VERSION` 등이 빠질 수 있다. 기존 빌드 폴더나 파티션을 지우거나 SDK 버전을 바꾸지 않았다.

2026-10-25 후속 구동 분리: JC1060 로컬 모터/외부 센서 역할을 제거하고 기존 독립 DriveMCU를 PC와 HMI에서 함께 제어하도록 변경했다. 위 이미지 해시는 음성 이식 당시 보존본이며 현재 소스의 구동 분리 빌드는 별도 기록을 따른다.
