# JC1060 SD 음성 및 HP/LP 스케줄러 소스 점검

## 반영 내용

한국어 14종(Windows Microsoft Heami), 영어 14종(Microsoft Zira)을 로컬에서 생성했다.
참여/제어 진입/조이스틱/레일/카메라/음성 탭/설정/정지 요청/재가동/연결 끊김/연결/
선별 시작/선별 완료 보고/안전 안내에 연결했다. 실제 정지나 물리적 선별 성공으로 단정하는 문장은 쓰지 않았다.

`ARD_ESP-IDF/JC1060P470C/sdcard/ard`를 SD카드 루트에 복사한다.
실제 SD카드 복사, 펌웨어 빌드, 플래시, 기기 재생은 수행하지 않았다.
음성 파일을 펌웨어 EMBED_FILES에 추가하지 않았으며 API 키나 네트워크 TTS를 사용하지 않았다.
기존 생성형 부팅/테스트음은 유지한다. NVS 설정값 저장은 음성 파일 저장과 별개로 유지한다.

## SD/PSRAM 처리

- WAV PCM16LE, mono, 16 kHz. 28개 PCM 데이터 합계 3,761,960 bytes. 최장 5.539초.
- `/sdcard/ard/voice/{ko,en}/{name}.wav`를 읽는다. 임의 경로를 원격 입력으로 받지 않는다.
- SDMMC slot0 / CLK43 CMD44 D0..3=39..42 / LDO4 / 10 MHz. C6는 기존 slot1을 사용한다.
  핀은 같은 JC1060 M4 프로젝트의 `main/include/board_storage.h`와 설치된 ESP-Hosted의
  `examples/host_sdcard_with_hosted`를 대조했다. 실제 보드 배선·SD/네트워크 동시동작은 미확인이다.
- 작업자 전용 PSRAM 2슬롯, 슬롯당 최대 512 KiB(총 상한 1 MiB). 실제 파일 크기만 할당한다.
  PSRAM 확보 실패/내부 RAM 여유가 64 KiB 미만이면 내부 RAM으로 대형 캐시를 대체하지 않고 SD에서 1 KiB씩 읽는다.
- 로컬 오디오 큐 8개(PCM 최대 8 KiB + 메타데이터). I2S 태스크는 파일을 열거나 읽지 않는다.
  출력은 기존 볼륨과 음소거를 따른다. 안내 ON/OFF는 기존 설정을 공유하며 미리 듣기는 안내 OFF에서도 가능하다.
- 일반 안내는 PC 응답/녹음/PTT/업로드/기존 재생과 겹치면 건너뛴다. 정지 요청 안내는 우선한다.
  제어 정지 명령은 음성 로딩을 기다리지 않는다. SD 오류 시 음성만 실패하고 UI/제어는 유지한다.
- 중단 시 세대 번호로 이전 PCM을 버린다. 큐 초기화로 새 재생 데이터를 지우는 경쟁을 피했다.
  카드 마운트 실패 시 자동 포맷하지 않는다. 재시도 간격은 30초이며, 사용 중 카드 교체는 재부팅 후 확인한다.
- 화면 보호기 장면은 음성과 반향 대기 0.5초가 들어가도록 5초에서 7초로 변경했다.

## 발견 사항과 변경

기존 활성 HMI 태스크에서 화면·오디오·통신이 HP0에 집중되어 있었다. 기존 `health`는
30초 간격의 힙/스택 출력만 있고, CPU 구간 사용률·처리 진행·LP 감시는 없었다.
이것은 소스에서 확인한 배치이며, 실제 과부하 발생을 측정한 결과는 아니다.

| 역할 | 코어 / 우선순위 | 변경 |
|---|---|---|
| I2S 읽기/쓰기, 캡처 | HP1 / 6 | HP0에서 이동. UI·네트워크·파일 접근 없음 |
| LVGL/터치 | HP1 / 4 | HP0에서 이동. 오디오는 I2S 대기로 UI 실행 기회 제공 |
| UDP 음성 수신 | HP0 / 5 | 16회 처리마다 1 tick 양보 |
| TCP 명령 | HP0 / 5 | 우선순위 10에서 조정. 연결 처리 뒤 1 tick 양보 |
| 수동구동 요청 전송 | HP0 / 4 | 전용 25 ms 태스크와 정지/재가동 경로 유지 |
| PC 상태/이미지 | HP0 / 3 | 한 번에 일반 명령 최대 4개. 연속 큐 입력 시 1 tick 양보 |
| 음성 업로드 | HP0 / 3 | 기존 큐 대기와 네트워크 분리 유지 |
| 네트워크 관리 | HP0 / 3 | 무지정 affinity에서 HP0 고정 |
| SD 음성, 설정, 콘솔 | HP0 / 2 | SD 작업자 추가, 콘솔 우선순위 9에서 조정 |
| 진단 | HP0 / 1 | 1초 대기, 30초 출력 또는 사용자 요청 |
| 진행 감시 | LP / FreeRTOS 외부 | 1초 타이머 IRQ, 나머지 WFI 대기 |

LP는 HP 태스크를 실행하는 세 번째 FreeRTOS 코어가 아니다. 작은 별도 프로그램이
HP가 갱신하는 UI/오디오 시퀀스를 읽고 5초 이상 정지 시 `stalled_mask`를 표시한다.
감시 자체의 `monitor_ticks`도 HP에서 확인한다. 주변장치·SD·PSRAM·I2S를 LP에서 공유하지 않고,
감시 실패로 자동 재부팅하거나 구동 명령을 보내지 않는다.
[Espressif LP 코어 문서](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/api-reference/system/ulp-lp-core.html)를 확인하고,
실제 API·ISR·CMake 구성은 로컬 ESP-IDF 5.5.5의 `examples/system/ulp/lp_core/lp_timer_interrupt`와 헤더를 따랐다.

## 진단 및 한계

- `scheduler_status`: 시리얼 전용. 약 1초 이내 HP 진단 요청 처리, SD 상태는 바로 출력.
- `HP0 busy`, `HP1 busy`: 두 idle 태스크의 구간 누적 실행시간과 ESP Timer 차이로 계산.
  첫 샘플은 기준값이다. 32-bit 랩어라운드는 unsigned 구간 차이를 사용한다.
- `UI/audio age`, `max_gap`: 부팅 후 각 처리 루프의 마지막 진행 시점과 최대 간격.
  오디오 실패 시 감시 비활성 상태를 따로 표시한다.
- 태스크별 768 bytes 미만의 스택 여유 경고, 내부/DMA/PSRAM 가용량, LP 카운터·정지 비트 출력.
- 양쪽 idle watchdog, 스택 카나리는 기존 설정을 유지했다. 기존 스케줄러/커널 버전은 변경하지 않았다.
- 실제 정상 동작 또는 성능 향상은 아직 증명되지 않았다. CPU 사용률/지연/음성 끊김/SDIO 동시 사용은 사용자 장치 로그가 필요하다.

## 수행한 비컴파일 검사

- ESP-IDF preflight: ESP32-P4 / 5.5.5 / LVGL 9.2.2. 새 HP 소스는 CMake에 등록됨.
  이전 컴파일 DB에 새 소스가 없는 경고는 남아 있으며 다음 사용자 빌드에서 생성해야 한다.
- 새 API 선언과 ULP 프로젝트 구성을 설치된 IDF의 헤더·예제로 대조했다.
- `python tools/verify_visitor_voice.py`: 28 WAV의 형식, RIFF 크기, 해시, 무음 여부, 파일 크기, 장면 시간 예산 통과.
- `python tools/check_ui_text.py`: 327개 키 검사. 기존/다른 작업 문구 5개 불일치가 남음:
  PID: ON, PID: OFF, Ready. Start sorting from the PC dashboard., PC update %s, START SORTING.
  새 안내 미리 듣기 문구는 번역표에 반영됨.
- 한국어 글꼴 데이터 재생성. 펌웨어·LP·시뮬레이터·호스트 실행파일 컴파일은 전혀 수행하지 않음.

## 사용자 실행

```powershell
& 'C:\Users\work\Desktop\ARD_v1\ARD_ESP-IDF\JC1060P470C\build.ps1' build
```

새 소스와 LP 프로그램, ULP 8 KiB 예약, FreeRTOS 런타임 통계가 다음 사용자 빌드에 적용된다.

AI 음성 동시 사용, SD 누락, 정지 요청을 확인한다. 카메라 미리보기+음성+연속 조작 중에도
`scheduler_status` 로그를 두 번 이상(30초 이상의 구간 포함) 얻어 CPU 사용률과 간격을 확인한다.
