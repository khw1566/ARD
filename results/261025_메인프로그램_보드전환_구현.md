# 메인프로그램 보드 구성 전환 — 2026-10-25

`ARD_MAIN`의 설정 → 일반/하드웨어 설정에 **사용 보드 및 제어 단말**을 추가했다.

## 사용 방법

1. 실행 중인 메인프로그램 서버를 다시 시작한다.
2. `/settings#tab-general`에서 보드 구성을 선택하고 **보드 구성 저장**을 누른다.
3. 이미 열려 있는 대시보드는 서버 이벤트로 갱신된다.

| 항목 | 선택 및 동작 |
|---|---|
| 3축 로봇 보드 | 사용/숨김. 끄면 상태 카드·제어·시뮬레이션을 숨기고, 수신 상태 알림 및 새 명령 전송을 차단한다. 브라우저 대기 명령과 시퀀스도 취소한다. |
| 제어 단말 | 구형 ControlMCU + HMI / JC1060P470C. 두 유닛을 번갈아 시연할 수 있다. |
| 음성 보드 | ControlMCU / JC1060. 단말 선택과 독립적으로 지정한다. JC1060 음성은 호환 음성 펌웨어 이식 후 사용한다. |
| JC1060 IP | 비워 두면 JC1060의 보드 식별 신호로 자동 감지한다. 직접 IPv4 주소를 지정할 수도 있다. |

처음에는 기존 구성과 호환되도록 **3축 로봇 사용 / 구형 단말 / ControlMCU 음성**을 선택한다. 저장한 구성은 `ARD_MAIN/backend/board_settings.json`에 유지하며 Git 추적 대상에서 제외한다. API 키나 비밀번호는 이 파일에 저장하지 않는다.

## 연결과 화면 처리

- 구형 HMI 시뮬레이터는 구형 단말에서 표시한다. JC1060 선택 시 통합 단말 연결 상태와 구동·카메라·음성 설정 바로가기를 표시한다.
- JC1060은 HMI/음성/게임패드 단말이며, 기존 DriveMCU는 독립 보드 그대로 유지한다. 단말·음성 설정을 바꿔도 DriveMCU IP·연결·구동 설정·명령 상태는 비우거나 JC1060으로 바꾸지 않는다.
- JC1060 식별 신호는 HMI 역할로만 수용한다. 알려진 JC1060 주소에서 오는 이전 `source=DriveMCU` 신호는 무시한다. 새 JC1060 펌웨어는 해당 신호를 전송하지 않는다.
- PC 및 JC1060 화면은 기존 DriveMCU API를 공유한다. 게임패드 조그는 별도 최신 입력 경로로 유한 스텝 명령을 보내며 PC 수동 조작·선별 시작 시 해제한다.
- 선택하지 않은 단말의 연결 신호가 현재 단말 IP를 덮어쓰지 않도록 구분한다. 단말 전환 시 이전 연결 상태와 보류 승인 작업을 비운다.
- 3축 로봇을 껐을 때 HTTP 명령, 구형 조이스틱 경유 명령, AI 도구 및 지연 승인 작업의 로봇 동작을 차단한다. 이는 PC에서의 표시 및 명령 제어이며 보드 전원 차단은 아니다.
- 음성 대상 IP를 선택한 보드로 연결하고, 음성 보드를 바꿀 때 이전 재생 큐와 녹음 버퍼를 비운다. 이번 작업은 PC 프로그램의 전환 기능이며 JC1060 음성 펌웨어 자체를 이식한 것은 아니다.

## 검증

- Python 회귀 검사 46개 통과: 새 보드 설정·라우트 검사 17개 및 기존 검사 29개.
- JavaScript 보드 전환·명령 큐 취소, 선별 대시보드, 구동 시뮬레이션 검사 통과.
- Python 문법 및 변경 JavaScript/인라인 스크립트 문법 검사 통과.
- 숨겨진 Edge와 실제 템플릿·정적 파일을 사용하는 로컬 Flask 테스트 서버에서 설정 표시, 저장 후 재접속 유지, 로봇 카드 숨김, JC1060 화면 전환, 구형 HMI 복귀, 활성 로봇 화면 이탈, 로봇 대기 큐 취소를 확인했다. JavaScript 예외는 0개였다.
- 브라우저 검증 서버는 AI·음성 작업자 및 실물 MCU와 분리한 테스트 환경이다. 실제 운영 서버 재시작, 실물 보드 간 전환 및 JC1060 음성 송수신 검증은 수행하지 않았다.
- 기존 로컬 수정본을 바탕으로 필요한 부분만 변경했다. 별도 작업 중인 펌웨어와 기존 ConfigManager 수정본을 보존했다.

검증 스크립트, 비교용 원본 및 화면 캡처는 Git에서 제외된 `tmp/board-settings-20261025/`에 있다.
