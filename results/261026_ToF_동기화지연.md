# DriveMCU ToF·레일 상태 동기화 지연

## 증상

DriveMCU의 TCP `status`(192.168.0.22:5002)는 0.5 s마다 바뀌는 `tof_mm`을 보고한다.
PC 화면(ARD_MAIN)과 JC1060 단말에는 ToF 거리와 레일 PID 상태가 늦게, 또는 틀리게 표시된다.

## 원인

1. PC가 ToF를 받는 경로는 DriveMCU 하트비트(HTTP POST `/api/heartbeat`) 하나였다. 기본 주기는 1000 ms(`mzh`)이다.
   하트비트에는 `tof_dist`만 있고 PID 상태, 레일 목표, 정착 여부는 없다.
2. JC1060은 `/api/status`(약 16 KB)를 3000 ms마다만 조회했다(`kPollMs`). 최대 4 s(하트비트 1 s + 조회 3 s) 늦게 표시되었다.
3. PC의 `drive_settings.pid_mode`와 `pid_target_tof`는 PC를 거친 명령의 기록일 뿐이었다.
   보드 실제값이 아니어서, 레일 도구·정렬 시퀀스·재부팅으로 바뀐 상태를 반영하지 못했다.
4. JC1060의 PID 버튼은 누르면 바로 ON이 되지만 다음 화면 갱신 때 PC의 옛 값으로 OFF로 돌아갔다. 목표(`railTarget`)는 보드 값과 다시 맞춰지지 않았다.
5. 브라우저는 `tof_status`를 읽지만 PC는 그 값을 저장하지 않았다. `drive_update` 이벤트는 `currentMotorState`를 덮어써 상태 표시를 지웠다.

## 수정

DriveMCU 펌웨어는 바꾸지 않았다. 보드의 TCP `status`가 이미 필요한 값을 모두 보고한다.

## 예상 지연

- PC 브라우저: 보드 값 → 약 0.3 s 안에 SSE로 표시(이전 최대 1 s + 화면 갱신).
- JC1060: 약 0.3 s(PC 폴링) + 0.5 s(단말 조회) 이내(이전 최대 4 s). JC1060 펌웨어를 다시 빌드해야 적용된다. 빌드 전에도 PC가 `/api/status`의 값을 최신으로 유지하므로 3 s 주기 안에서는 최신 값이 보인다.
