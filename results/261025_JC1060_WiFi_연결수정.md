# JC1060 Wi-Fi 자동·수동 연결 수정 (2026-10-25)

사용자 증상: 주변 공유기 목록은 표시되지만 자동·수동 연결에 실패함.

## 확인 및 수정

- 자동 연결은 공유기에 무선 연결된 뒤에도 최초 연결 요청 기준 12초에 연결을 종료했다. PC 이벤트 테스트로 DHCP 응답이 13초에 오는 경우의 조기 종료를 재현했다. 인증 대기 12초와 무선 연결 이후 DHCP 대기 30초를 분리했다.
- 수동 연결은 `wifi_ops`를 잡은 채 IP만 기다려 공통 연결 관리 코드가 실행되지 않았다. 수동 대기 루프에서 연결 관리 코드를 실행하고, 선택 SSID에만 최대 2회 추가 재시도하도록 했다. 실패한 프로필은 성공 이력으로 저장하지 않는다.
- 수동 연결·복구 및 검색 중 연결 해제는 고정 200ms 대기를 사용했다. 실제 해제 이벤트를 최대 2.5초 기다리도록 했다. 이벤트가 누락되면 새 프로필을 적용하지 않는다.
- 자동·수동 연결의 공통 설정에 SAE 양쪽 방식(H2E 포함)과 선택적 PMF를 명시했다. 사용자 공유기의 실제 인증 방식은 미확인이므로 이를 이번 증상의 확정 원인으로 판단하지 않는다.
- 초기 인증 실패도 시리얼에 `Wi-Fi disconnected (reason N)`을 남기고 무선 연결 직후 DHCP 대기 시작도 기록한다.

공통 코드 `ARD_ESP-IDF/shared/ard_wifi.c`를 사용하므로 다음 빌드 때 다른 ESP-IDF 보드에도 공통 연결 설정·DHCP 처리 변경이 적용된다. JC1060의 수동 연결 처리는 해당 보드의 `components/ard_net/ard_network.c`에서 수정했다. 기존 작업 중인 다른 기능 변경은 되돌리지 않았다.

## 검증

- `python ARD_ESP-IDF/shared/test/run_clang_tests.py`: 종료 코드 0, 20개 테스트 통과. 실제 연결 관리 C 코드를 PC Wi-Fi/NVS 대체 함수로 실행한다.
- 신규 테스트: DHCP 지연, 보안 설정, 수동 재시도 제한과 성공, 700ms 연결 해제 지연, 해제 이벤트 누락, 수동 연결 중 IP 소실.
- `node ARD_ESP-IDF/shared/test/test_portal.js`: 종료 코드 0, 웹 검색·선택·재시도 검사 통과.
- 설치된 ESP-IDF 5.5.5 헤더에서 이벤트·SAE/PMF 필드를 확인했다. preflight의 JC1060 타깃은 esp32p4이며 메타데이터 검사 결과 findings 없음.
- 변경 파일 `git diff --check`: 종료 코드 0.
- 기존 MSVC 실행기는 해당 설치가 없어 실행하지 못했다. 설치된 Unity WebGL Clang의 x86-64 대상과 Windows CRT를 사용하는 대체 실행기를 추가해 위 PC 테스트를 수행했다. 테스트 실행에는 장치나 시리얼 포트를 사용하지 않았다.

이번 작업에서는 타깃 펌웨어 빌드·링크·플래시, 실제 공유기 인증·DHCP·재부팅 후 자동 연결을 검증하지 않았다. PC 회귀 테스트 결과는 실물 연결 성공의 증거가 아니다.

## 실물 확인

JC1060 프로젝트 폴더에서 `./build.ps1`로 빌드하고 실제 P4 포트를 지정해 업로드한다. 재부팅 자동 연결, 터치 수동 연결, 비밀번호 오류 후 복구를 확인한다. 실패가 계속되면 부팅부터 `ARD_NET`, `ARD_WIFI`, ESP-Hosted 메시지가 포함된 시리얼 로그와 reason 코드를 확인한다. 실제 비밀번호는 로그에 추가하지 않는다.
