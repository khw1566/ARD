## 확인한 오류와 수정

1. 빌드 스크립트의 Python과 기존 CMakeCache의 Python이 달라 시작 단계에서 실패했다.
   `build.ps1`이 설치되어 있는 기존 IDF 5.5 Python을 재사용하도록 수정했다. fullclean하지 않았다.
2. 첫 실제 컴파일 원인은 LP 하위 프로그램의 `esp_adc/adc_oneshot.h` 누락이었다.
   LP CMake가 메인 컴포넌트의 공개 include 경로를 상속하므로 `esp_adc`를 공개 REQUIRES로 등록했다.
   설치된 SDK 소스를 수정하지 않았다.
3. 첫 실제 SD 업로드는 FAT 긴 파일명 지원이 꺼져 `.wav.upload` 임시 파일 열기에 실패했다.
   `FATFS_LFN_HEAP=y`, 최대 이름 길이 96을 적용해 재빌드·재플래시한 뒤 28개 전송을 완료했다.
4. 기본 1 KiB IPC 시스템 태스크의 정상적인 708/716 bytes 스택 여유가 앱 기준 경고로 표시됐다.
   앱 태스크 경고 768 bytes와 작은 시스템 태스크 경고 256 bytes를 구분했다. 스택 카나리는 유지했다.

## 추가한 전송 경로

- `GET /api/voice/status`: 프로토콜·SD 상태·요청 토큰. 토큰을 결과 기록이나 콘솔에 출력하지 않는다.
- `POST /api/voice/file?lang=ko|en&name=<안내 이름>`: 기존 보드 요청 토큰과 원본 SHA-256 필요.
- `GET /api/voice/file?...`: 실제 SD 파일의 크기와 SHA-256 반환.
- 경로는 고정된 14개 안내 이름과 두 언어만 허용한다. WAV 길이·PCM 형식 검증 후 임시 파일을 확정한다.
  기존 파일은 `.bak`에 보존하며, 오류 시 기존 파일을 유지한다. 업로드와 재생의 파일·캐시 접근은 mutex로 직렬화했다.
- 업로드 도구: `ARD_ESP-IDF/JC1060P470C/tools/upload_visitor_voice.py`.
  가짜 HTTP 전송을 이용한 요청/검증 흐름 검사 후 실제 장치로 전송했다.

```powershell
python tools/upload_visitor_voice.py --host 192.168.0.30
python tools/upload_visitor_voice.py --host 192.168.0.30 --verify-only
```

## 최종 실행 관찰

웹 업로드와 겹친 최종 USB 출력 관찰은 45초다. 측정된 한 CPU 구간은 약 31.01초이며 다음을 보고했다.

| 항목 | 실제 로그 |
|---|---|
| HP0 사용률 | 27% |
| HP1 사용률 | 59% |
| 태스크 수 | 27 |
| UI 갱신 최대 간격 | 265 ms (250 ms 갱신 타이머 기준) |
| I2S 오디오 루프 최대 간격 | 17 ms |
| LP | ready=1, ticks=60, stalled_mask=0 |
| 내부 가용 힙 / DMA 가용 힙 | 196,907 / 167,083 bytes |
| PSRAM 가용량 | 26,789,880 bytes |

이 관찰 구간에서 패닉·assert·watchdog 재부팅 로그는 없었다. 최종 빌드와 부팅·SD 저장 및 읽기는
실제로 확인했다. 스피커의 실제 청취, 화면을 직접 누르는 조작, 로봇 이동 및 장시간 최대 부하 검증은 수행하지 않았다.
