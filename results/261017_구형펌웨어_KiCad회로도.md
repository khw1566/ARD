# ARD 구형 펌웨어 기반 KiCad 회로도

## 결과물과 사용법

`results/kicad_legacy_261017/ARD_Legacy.kicad_pro`를 KiCad 10에서 열고 회로도 편집기를 실행한다. 첫 시트의 하위 시트를 열면 MCU별 상세 회로도가 나타난다. `.kicad_sch`를 직접 열어도 된다. 심볼 라이브러리 `ARD.kicad_sym` 및 `sym-lib-table`을 같은 폴더에 보관한다.

- `ARD_Legacy.pdf`: A3 가로 7쪽, 검색 가능한 한글 텍스트와 회로도.
- `presentation_png/`: 발표에 바로 삽입할 1920×1080 이미지 7장. KiCad 출력에서 회로 영역을 확대하고 모든 주석을 함께 배치했다.
- `svg/`: 확대해도 선명한 KiCad 벡터 출력 7장.
- `png/`: 도면 전체를 보존한 가로 3600px 이미지 7장.
- `pinmap.csv`: 연결 78행, GPIO·부품·단자·근거 소스 경로와 행 번호.
- `module_bom.csv`: 펌웨어에 등장하는 모듈 구성과 수량, 확정 수준.
- `source_manifest.json`: 근거 파일 SHA-256, 시트별 모듈과 넷 목록.
- `ARD_Legacy.net.xml`, `erc.rpt`, `validation.json`: KiCad 넷리스트와 검증 결과.
- `generate_schematics.py`, `verify_and_render.py`: 재생성 및 대조·렌더링 스크립트.

## 시트 구성

| 쪽 | 내용 | 주요 부품 |
| --- | --- | --- |
| 1 | 시스템 전체 및 Wi-Fi 통신 흐름 | PC Center, 기존 5개 MCU |
| 2 | ControlMCU 조작·오디오 | ESP32-S3, 조이스틱, 토글, 버튼, MAX98357A, WS2812B |
| 3 | DriveMCU 3축 구동 | ESP32-WROOM32D, A4988 ×3 |
| 4 | DriveMCU 센서·조작 | NEO-6M, SSD1306, AHT20, BMP280, VL53L0X, 버튼·가변저항·버저 |
| 5 | Robot3AxisMCU | ESP32-S3, 3축 STEP/DIR 드라이버, 4채널 릴레이, L298N |
| 6 | ImageSenderMCU | ESP32-S3 N16R8, DVP 카메라 |
| 7 | HMI_MCU | ESP32-2432S028, ILI9341, XPT2046 |

전체 구성도의 선은 네트워크 통신 흐름이며 전기적 넷이 아니다. 상세 회로도의 동일 라벨은 해당 시트 안에서 전기적으로 연결된다. 예를 들어 `D_G18`은 DriveMCU GPIO18이다. `C`, `D`, `R`, `CAM`, `H` 접두어로 MCU별 신호를 구분했다. GPIO 번호는 MCU 신호 식별자이며 실제 보드 헤더의 몇 번째 핀인지 표시한 것이 아니다.

## 현재 소스를 우선한 주요 핀맵

### ControlMCU

- 조이스틱 UP/DOWN/LEFT/RIGHT: GPIO47/21/13/14.
- 토글 A/B: GPIO35/36. 푸시 버튼 GPIO11. 모두 `INPUT_PULLUP`.
- 버튼 표시 LED GPIO4, 내장 WS2812B GPIO48.
- MAX98357A DIN/LRC/BCLK/SD: GPIO40/41/42/39.
- 스위치의 공통 단자가 GND라는 해석은 내부 풀업 사용에 근거한 배선 추론이다. 실물 확인이 필요하다.
- 코드 주석에는 N16R8이지만 ControlMCU의 빌드 파일에는 PSRAM 구성 확정 정보가 없다. 실제 보드가 Octal PSRAM을 사용하는 N16R8이면 GPIO35/36은 PSRAM 신호와 충돌할 수 있다. 원본 배정은 수정하지 않았다. [Espressif 회로 체크리스트](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html)

### DriveMCU

- X STEP/DIR/EN: GPIO18/19/21.
- Y STEP/DIR/EN: GPIO16/17/5.
- Z STEP/DIR/EN: GPIO25/26/27. 기존 요약 문서의 2축 설명과 달리 실제 코드는 3축이다.
- I2C SDA/SCL: GPIO22/23. SSD1306 0x3C, AHT20 0x38, BMP280 0x76 실패 시 0x77.
- VL53L0X는 연결 인터페이스를 표시하되 현재 `ARD_ENABLE_TOF=0`으로 기본 비활성 상태임을 표시했다.
- GPS TX→MCU GPIO32(RX), MCU GPIO33(TX)→GPS RX, UART2 9600 8N1. `enableGPS=false`가 기본이므로 연결 지원과 실제 기본 동작을 구분한다.
- 수동 버튼 GPIO13/14, 가변저항 와이퍼 GPIO34, 수동 버저 구동 GPIO4.

### Robot3AxisMCU

- X STEP/DIR/EN: GPIO9/10/11.
- Y STEP/DIR/EN: GPIO12/13/14.
- Z STEP/DIR/EN: GPIO8/3/46.
- 릴레이 IN1~4: GPIO4/5/6/7, active LOW. 주석상 CH1/2가 공압 그리퍼에 사용된다.
- L298N IN1~4: GPIO15/16/17/18.
- 이 MCU의 스텝 드라이버 형식은 소스에 명시되지 않아 A4988로 단정하지 않았다.
- GPIO3/46은 스트랩 핀이므로 연결된 외부 회로가 부팅 레벨에 미치는 영향을 확인해야 한다. [Espressif 회로 체크리스트](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html)

### ImageSenderMCU

- `config.pin_d0~d7`와 실제 Y2~Y9 정의를 대응해 D0~D7=GPIO11/9/8/10/12/18/17/16으로 작성했다.
- XCLK/PCLK/VSYNC/HREF: GPIO15/13/6/7.
- SCCB SDA/SCL: GPIO4/5.
- PWDN/RESET=-1: MCU가 해당 신호를 구동하지 않는다. 모듈 자체 회로에서 어떻게 처리되는지는 미확정이다.
- 기존 문서의 데이터 배열과 현재 소스가 다르다. 회로도에는 현재 소스를 반영했다.
- 문서에 OV5660/OV5640 표현이 혼재하므로 카메라의 정확한 SKU는 미확정이다. 현재 소스에 없는 SD 카드 배선은 추가하지 않았다.

### HMI_MCU

- ILI9341 MOSI/MISO/SCLK/CS/DC/BL: GPIO13/12/14/15/2/21. `platformio.ini`의 실제 TFT_eSPI 설정 기준.
- XPT2046 MOSI/MISO/CLK/CS/IRQ: GPIO32/39/25/33/36. 실제 `main.cpp`가 사용하는 `CYD28_TouchscreenR.h` 기준.
- 터치와 LCD는 별도 SPI 신호를 사용한다. 보드 내부 기능 신호를 나타내며 외부 점퍼 배선 지시가 아니다.
- TFT RST=-1, BL은 제어 신호다. 백라이트의 실제 전류 구동 회로는 복원하지 않았다.

## 범위와 미확정 항목

이 결과물은 **발표용 모듈 단위 신호 연결 회로도**이다. 소스만으로 실제 개발보드 내부 회로와 전원회로를 복원할 수 없어, MCU·드라이버·센서·LCD 등의 인터페이스를 사용자 정의 KiCad 심볼로 표현했다. 표준 IC 패키지 핀 번호, PCB 풋프린트 또는 커넥터 핀 순서를 임의로 배정하지 않았다.

전원·접지·코일·릴레이 접점·스피커·설정 핀 중 코드로 확인할 수 없는 64개 단자는 미확정 또는 보드 내부 단자로 표시했다. 이 단자의 X 표시는 KiCad상 미연결 표식이지만, **실제 제작 시 해당 단자를 연결하지 않아도 된다는 뜻이 아니다.** 실제 접지 공통 연결, 센서 모듈의 레귤레이터와 풀업, A4988 VMOT/VDD/RESET/SLEEP/MS1~3, 모터 전류 제한, L298N ENA/ENB, 릴레이 절연·접점 정격, LED 저항, 전원 용량·보호회로는 실물과 모듈 데이터시트 확인 후 설계해야 한다.

`ImageSenderMCU_P4`는 기존 S3의 대체 카메라 보드라 본 도면에서 제외했다. `D2/TEST` 실험 프로젝트도 제외했다. 이전 문서의 SoundMCU는 현재 해당 소스 폴더가 없어 별도 MCU로 추가하지 않았다. 원본 펌웨어는 변경하지 않았다.

## 검증 결과

- KiCad CLI 10.0.3으로 7개 시트 로드 및 PDF/SVG/넷리스트 출력 성공.
- ERC 오류 0, 경고 0. 심볼은 모두 passive 논리 포트이며 GPIO 입출력 적합성이나 전원 전기 특성은 검사 범위 밖이다. 미확정 단자에는 의도적으로 NC 표식을 붙였다.
- 78개 연결을 KiCad 출력 넷리스트와 대조해 모두 일치. 공유 I2C를 포함한 실제 신호 넷 72개. 의도하지 않은 신호 넷 병합 또는 추가 연결 없음.
- 근거 파일 SHA-256 일치 확인. 릴레이와 L298N GPIO 배열도 소스와 대조했다.
- PDF 7쪽과 한글 출력 확인. 전체 시트 미리보기 및 대표 상세 이미지의 핀 라벨·주석·배치 확인.
- 실제 배선, 전압, 전류, 보드 부팅, 모터·센서 동작 또는 PCB 제조 검증은 수행하지 않았다.
- 제한된 실행 환경에서 KiCad가 사용자 설정 레지스트리 접근 경고를 출력했지만, 최종 파일 출력과 ERC는 완료되었다.

## 재생성

먼저 `python -X utf8 generate_schematics.py`를 실행한다. 이후 KiCad CLI의 `sch export pdf`, `sch export svg`, `sch export netlist --format kicadxml`, `sch erc`를 사용해 원본 프로젝트를 출력한다. PDF/SVG 출력 시 한글 폰트 옵션 `--default-font "Malgun Gothic"`을 사용한다. 마지막으로 `pypdf`, `Pillow`, `pypdfium2`가 있는 Python에서 `verify_and_render.py`를 실행하면 신호 넷 대조와 PNG 생성이 수행된다. [KiCad CLI 공식 문서](https://docs.kicad.org/master/en/cli/cli.html)
