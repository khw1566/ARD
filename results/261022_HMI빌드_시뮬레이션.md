# 시뮬레이션

Espressif QEMU 9.2.2 (`esp_develop_9.2.2_20260417`)에서 ESP32 검증용 펌웨어를 실행했습니다.
화면을 다시 그린 JavaScript 모형이 아니라 실제 펌웨어의 `gfx.c`, `hmi_ui.c`, `hmi_setup.c`, QR 생성 코드를 컴파일해서 실행했습니다.
장치 통신에는 고정된 시험 데이터를 공급하며, 연결 관리 코드는 가짜 Wi-Fi/NVS 이벤트로 구동합니다.

연결 관리 테스트 7개가 모두 통과했습니다.

- 성공 기록 16개 제한 및 가장 오래된 성공 항목 교체, 같은 SSID 비밀번호 갱신.
- 검색에 나타난 저장 SSID만 연결, 중복 SSID 제거, 성공 후 기록 갱신 및 재연결 전 새 검색.
- 실패한 새 자격 증명을 성공 기록에 저장하지 않음.
- 같은 SSID의 새 비밀번호 실패 시 이전 성공 비밀번호 재시도.
- 연결 시간 초과 후 다른 검색된 후보로 진행.
- 스캔 실패 시 연결·저장하지 않음.
- NVS 저장 실패 시 연결을 유지하며 저장 재시도.

화면 검증도 통과했습니다.

- 네트워크 화면에서 다음 페이지 입력으로 화면이 바뀜.
- Wi-Fi QR과 웹 QR을 실제 화면 버퍼에서 캡처.
- 캡처한 QR 두 개를 jsQR 1.4.0으로 판독하고 기대 내용과 완전히 일치함을 확인.
- Wi-Fi QR: `WIFI:T:WPA;S:ard-hmi-123456;P:ARD-123456!;;`.
- 웹 QR: `http://192.168.4.1/network`.
- QR 화면을 닫고 원래 페이지를 다시 그린 결과가 기존 페이지 버퍼와 완전히 일치함.

시뮬레이터의 전체 화면 캡처 버퍼는 ESP32의 정적 메모리 한도와 여러 힙 영역을 고려해 작은 밴드로 나눠 할당했습니다. 실제 HMI 펌웨어의 메모리 배치는 변경하지 않았습니다.

# 재현 명령 및 증거

HMI 프로젝트 폴더에서 실행합니다.

```powershell
.\build.ps1 -BuildDir build-codex-check
.\build.ps1 -ProjectDir .\test\sim -BuildDir build
```

두 빌드 모두 종료 코드 0입니다. 저장소 루트에서 실행합니다.

```powershell
python -u ARD_ESP-IDF/HMI_MCU/test/sim/run_sim.py
```

시뮬레이션·화면 판독 스크립트 종료 코드 0입니다. QEMU는 시험 완료 마커를 출력한 뒤 스크립트에서 종료합니다.

- 실제 빌드 로그: `261022_HMI_build.log`.
- 시뮬레이터 빌드 로그: `261022_HMI_sim_build.log`.
- 시뮬레이터 출력: `261022_HMI_sim/qemu.log`.
- 화면: `261022_HMI_sim/preview.png`, `network.png`, `drive.png`, `wifi-qr.png`, `web-qr.png`, `returned.png`.
