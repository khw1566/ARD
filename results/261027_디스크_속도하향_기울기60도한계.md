# 디스크 원점 오차 대책: 속도 하향, 기울기 ±60° 안전 한계

## 요청
디스크 원점 오차(오버슛, 탈조) 대책을 세운다. 먼저 최대 속도를 낮춘다. 기울기는 ±60°를 넘지 않게 제한하고, 디스크 회전은 예외로 둔다.

## 기구학
- 모터 1스텝 = 1.8°, 4:1 감속 후 0.45°.
- 기울기 φ = (X − Y)/2 × 0.45°, 회전 ψ = (X + Y)/2 × 0.45°. PC `tilt_steps` 기준으로 전진 전도는 +X/−Y입니다.
- ±60° 한계는 |X − Y| ≤ 266스텝(59.85°)입니다. 시퀀스의 45° 전도(X − Y = 200)는 한계 안입니다.

## DriveMCU 변경 (`ARD_ESP-IDF/DriveMCU/main`)
| 항목 | 내용 |
|---|---|
| 속도 | X/Y 기본 500 → 300 steps/s, 가속 500 → 300 steps/s². `mxs`/`mys` 상한 300. Z는 그대로 |
| 이동 검사 | `b`·`df`/`db`/`dr`/`dl`·`mxr`·`myr`의 끝 기울기를 계산합니다(실행 중인 이동과 큐 포함). 한계 밖이면 `ERR:REJECTED`. 큐에서 꺼낼 때 다시 검사하고, 거부되면 큐를 비웁니다 |
| 조그 | 한계 2스텝 안쪽 소프트 월. 상대 축의 정지 위치 기준으로 제한. 스틱 반전 시 제한된 정지점으로 먼저 감속 |
| 백스톱 | 한계를 넘어 더 벌어지면 X/Y 즉시 정지, 프로그램 삭제 |
| 상태 | `tilt_deg`, `tilt_limit_deg`, `tilt_limit_count`, `tilt_limit` |
| 설정 | menuconfig `ARD_DISK_MAX_SPEED`(300), `ARD_DISK_ACCEL`(300), `ARD_DISK_TILT_LIMIT_DEG`(60), `ARD_DISK_GEAR_RATIO`(4) |

파일: `motion.cpp`, `motion.h`, `board.h`, `Kconfig.projbuild`, `command_servers.cpp`, `commands.cpp`(도움말), `README.md`.
다른 스레드에서 진행 중인 Z 70~120 mm 한계, 조그, 시퀀스 변경은 그대로 두고 그 위에 덧붙였습니다.

## PC 변경 (`ARD_MAIN`)
- `core/rail_control.py`: `TILT_LIMIT_DEG = 60`. 시퀀스 전도 각도 설정 범위를 5~90°에서 5~60°로 바꿨습니다. `tilt_steps`는 60°를 넘으면 예외를 냅니다. `disc_tilt_error()`를 추가했습니다(펌웨어와 같은 규칙).
- `app.py` `/api/drivemcu/command`: 수동 디스크 명령을 보내기 전에 검사합니다. 한계를 넘으면 409와 사유를 돌려줍니다.
- `core/sorting_pipeline.py`: 이동 중 `tilt_limit_count`가 늘면 시퀀스를 오류로 멈춥니다.
- HMI와 JC1060은 PC를 거쳐 DriveMCU로 명령을 보냅니다. 따라서 펌웨어 한계가 그대로 적용됩니다. JC1060 조그(`j`)는 소프트 월에서 멈춥니다.
