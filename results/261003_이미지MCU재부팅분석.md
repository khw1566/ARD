# 이미지 MCU 무한 재부팅 문제 분석 및 조치 보고서

## 1. 문제 개요
ESP32-S3 이미지 MCU에 펌웨어를 업로드한 뒤 부팅과 재부팅이 반복됐다. 시리얼 모니터에는 Brownout 감지 메시지가 출력됐고, 사용자 프로그램의 시작 메시지는 확인되지 않았다. ESP-IDF 별도 프로젝트는 사용하지 않았으며, Arduino 기반 ImageSenderMCU를 대상으로 분석 및 수정했다.

수정 후 사용자 제공 로그에서 프로그램 시작, NVS 설정 로드, Wi-Fi 연결, 카메라 초기화 및 setup 완료를 확인했다. 가장 유력한 원인은 setup 첫 줄의 Brownout 제어 레지스터 직접 쓰기다. 다만 시작 대기 제거와 로그 추가도 함께 적용했으므로 특정 한 줄의 인과관계를 독립적으로 재현한 결과는 아니다.

## 2. 환경 및 사용자 확인 사항
| 항목 | 확인 내용 |
|---|---|
| MCU | ESP32-S3 |
| 개발 환경 | Arduino framework, PlatformIO |
| SDK | 성공 로그 기준 v5.5.5 |
| CPU | 160MHz |
| PSRAM | OPI 설정, 정상 인식 용량 8,388,608 bytes |
| 시리얼 | COM13, 115200 baud, 8-N-1 |
| 카메라 설정 | 소스 기본 센서명 OV3660, SVGA, JPEG quality 12, 버퍼 2개 |
| 연결 | 보드 기본 USB-C UART 포트는 PC, USB-OTG 포트는 30W 휴대폰 충전기에 연결했다고 사용자 설명 |
| 비교 모듈 | 기존 2개와 새로 구매한 1개에서 동일 증상이라고 사용자 설명 |

카메라 센서명은 소스 설정값이며 실제 센서 식별값을 별도로 검증하지 않았다. 전원 연결과 모듈 비교 결과는 사용자 설명에 기반하며, MCU 전원 레일의 전압 파형을 측정하지는 않았다.

## 3. 최초 증상과 조사 방향
최초 시리얼 로그의 주요 내용은 다음과 같다.

```text
ESP-ROM:esp32s3-20210327
rst:0x3 (RTC_SW_SYS_RST),boot:0x8 (SPI_FAST_FLASH_BOOT)
Saved PC:0x40376e61
entry 0x403c88b8
E BOD: Brownout detector was triggered
```

Brownout 메시지는 SDK의 저전압 감지 처리 경로가 재부팅을 발생시켰다는 근거다. 이 메시지만으로 외부 전원 공급 부족, 보드 불량 또는 소프트웨어 설정 문제 중 하나를 확정할 수는 없다.

초기에는 공급 능력 부족을 우선 의심했으나, 사용자가 별도 충전기 사용과 세 모듈의 동일 증상을 설명한 뒤 공통 소프트웨어 설정을 중심으로 비교했다. 당시 setup 첫 줄에 레지스터 쓰기가 있었고 시작 로그 앞에는 2초 대기가 있었으므로, 시작 로그가 없다는 사실만으로 setup 진입 이전의 실패라고 단정할 수도 없었다.

## 4. 비교 진단 결과
| 진단 환경 | 설정 및 제외 기능 | 실기기 결과 |
|---|---|---|
| power-diagnostic | DIO Flash, CPU 80MHz, PSRAM 비활성; Wi-Fi·카메라 미사용 | Alive 로그 반복, 기본 부팅 정상 |
| psram-diagnostic | QIO Flash, OPI PSRAM, CPU 160MHz; Wi-Fi·카메라 미사용 | PSRAM 8MB 인식 및 Alive 출력 정상 |
| psram-dio-diagnostic | 위 환경에서 Flash 모드만 DIO로 변경 | PSRAM 8MB 인식 및 Alive 출력 정상 |
| 수정된 본 펌웨어 | QIO/OPI 설정 유지, Wi-Fi·카메라 실행 | Wi-Fi 연결, 카메라 ESP_OK, setup 완료 |

두 PSRAM 진단의 공통 출력은 다음과 같다.

```text
[POWER TEST] Setup reached. Reset reason: 1
[POWER TEST] SDK: v5.5.5, CPU: 160 MHz
[POWER TEST] PSRAM found: yes, size: 8388608, free: 8384788 bytes
[POWER TEST] PSRAM startup enabled; Camera/WiFi are idle.
```

이 결과로 QIO/DIO Flash 선택과 OPI PSRAM 초기화 실패를 우선 원인에서 제외했다. 주변 장치가 없는 진단의 성공만으로 실제 촬영·전송 부하에서의 전원 안정성까지 보장할 수는 없다.

## 5. 원인 분석
기존 setup 첫 줄에는 다음 코드가 있었다.

```cpp
WRITE_PERI_REG(RTC_CNTL_BROWN_OUT_REG, 0);
```

Brownout 감지를 끄려는 목적으로 제어 레지스터 전체를 직접 덮어쓰는 코드다. SDK가 관리하는 감지·리셋 제어 상태를 사용자 코드에서 직접 변경하므로 SDK의 설정 및 처리 경로와 불일치할 가능성이 있다.

이 코드를 제거하고 SDK의 Brownout 보호를 유지한 상태에서 본 펌웨어가 정상 부팅했다. 메모리 진단도 정상이었으므로 직접 레지스터 쓰기가 가장 유력한 원인 후보다. 그러나 어떤 레지스터 필드나 인터럽트 상태가 재부팅을 유발했는지는 계측하지 않았고, 해당 코드만 다시 적용하는 재현 실험도 수행하지 않았다. 따라서 결론은 ‘수정 후 해결 확인, 직접 레지스터 쓰기가 유력한 원인’으로 기록한다.

Arduino 단독 빌드는 사전 컴파일된 SDK를 사용하므로 프로젝트의 sdkconfig.defaults에 감지 비활성화 설정을 적는 것만으로 SDK 설정이 재빌드되지는 않는다. 해당 파일의 존재를 실제 Brownout 비활성화 근거로 사용해서는 안 된다.

## 6. 수정 내용
- main.cpp의 Brownout 레지스터 직접 쓰기 및 불필요한 관련 헤더 제거.
- 시작 로그 앞의 delay(2000) 제거로 setup 진입 즉시 상태 출력.
- setup, NVS, Wi-Fi, 카메라 초기화에 Stage 1~4 로그 추가.
- 주요 단계의 Serial.flush로 다음 동작 전에 진단 메시지 전송.
- 재부팅 원인, SDK, CPU, 힙 및 PSRAM 용량 출력.
- esp_camera_init 반환값을 오류 이름과 숫자 코드로 출력.
- 카메라 설정 구조체를 0으로 초기화.
- 누락된 촬영·전송 시간 변수 선언 및 비활성 TCP 코드의 빌드 오류 정리.
- platformio.ini에 세 진단 환경 추가. 기본 환경은 본 펌웨어로 유지.
- POWER_DIAGNOSTIC.md, 설정 가이드 및 코드 인덱스에 진단 방법 반영.

진단 환경과 수정된 본 펌웨어는 PlatformIO 빌드에 성공했다. 실기기 업로드와 실행 로그는 사용자가 제공했다. 에이전트가 직접 보드를 조작하거나 전압을 측정한 것은 아니다.

## 7. 수정 후 검증
사용자 제공 성공 로그의 주요 부분은 다음과 같다.

```text
=== TRANSMITTER SYSTEM ONLINE ===
[Boot] Stage 1: setup entered; SDK brownout protection retained
[Boot] Reset reason: 1, heap: 303728, PSRAM: 8388608 bytes
[Boot] SDK: v5.5.5, CPU: 160 MHz
[Boot] Stage 2: loading NVS settings
[Boot] Stage 2 complete
[Boot] Stage 3: WiFi configuration/start
[Boot] WiFi.begin returned
WiFi Connected Success!
Local IP: 192.168.0.100
[Boot] Stage 4: camera initialization
[Camera] Calling esp_camera_init: PSRAM=yes, fb_count=2
[Camera] esp_camera_init returned: ESP_OK (0x0)
Camera Init: SVGA (Q:12)
[Boot] Setup complete. Type 'c' to capture
```

사용자도 성공을 확인했다. 이 로그는 부팅 루프 해소, NVS 처리 진행, Wi-Fi 연결 및 카메라 초기화 성공의 근거다. 실제 사진 촬영, UDP/HTTP 전송, 장시간 연속 운전은 아직 검증되지 않았다.

## 8. 별도 남은 사항
성공 로그에는 HTTP 요청의 connection refused 메시지가 남았다. 해당 실패 뒤에도 카메라 초기화와 setup 완료까지 진행했으므로 이번 부팅 루프와 별도로 처리해야 한다.

HTTP 연결 실패의 구체적 원인은 확인되지 않았다. PC 서버 실행 여부, 선택된 server_ip와 5000번 포트, 방화벽 및 네트워크 접근성을 확인해야 한다. Wi-Fi 연결 성공만으로 PC 서버 접근 가능성이 입증되지는 않는다.

## 9. 재발 방지 및 후속 검증
- Brownout 제어 레지스터를 직접 덮어쓰는 코드를 다시 추가하지 않는다.
- 재발 시 마지막 Stage 로그와 재부팅 로그 한 주기를 함께 보관한다.
- SDK 버전과 정상 동작한 메모리 설정을 기록하고 비교 시 한 번에 하나의 조건을 변경한다.
- 서버 연결 복구 후 시리얼 c 명령으로 촬영 및 실제 수신 여부를 확인한다.
- 반복 촬영, Wi-Fi 재연결 및 장시간 운전에서 재부팅 여부를 추가 확인한다.
