# JC1060 연속 제어를 속도 조그로 변경

## 원인
JC1060 조이스틱은 PC를 거쳐 DriveMCU에 `b20,-20` 같은 20스텝 이동을 보냈고, PC는 앞 이동이 끝나야(`busy=false`) 다음 20스텝을 보냈습니다.
가속도 500 step/s²에서 20스텝은 가속·감속만으로 약 0.4초가 걸리고 최고 속도는 100 step/s입니다.
여기에 상태 확인·TCP 왕복·명령 간격이 더해져 실효 속도는 약 40~50 step/s였고, 20스텝마다 멈췄다 출발해 끊겨 보였습니다.
손을 뗄 때는 비상정지 `x`로 드라이버까지 꺼서, 하중이 걸린 축이 밀릴 수 있었습니다.

## 변경
| 위치 | 내용 |
|---|---|
| DriveMCU `motion.*` | 연속 조그 추가. 모터별 목표 속도를 축 가속도로 램프. 400ms 데드맨. 최고 속도는 `mxs`/`mys` 설정(기본 500)을 넘지 않음. 큐·귀환·PID 동작 중 거부. 조그 갱신 시각 비교를 부호 있는 값으로 처리(락 대기 후 1틱 정지 방지) |
| DriveMCU `commands.cpp`, `CommandValidation.h` | `j<x>,<y>,<z>` (-1000~1000‰) 명령·검증. 조그 명령은 효과음·시리얼 출력 생략 |
| DriveMCU `command_servers.cpp` | `status`에 `jogging` 추가(조그 지원 표시) |
| PC `api/jc1060_drive_routes.py` | 조그 지원 보드면 조이스틱을 `j` 속도 스트림으로 전달. 놓으면 `j0,0,0`(감속 정지). 상태 확인은 0.5초마다(재부팅·PID·다른 이동 감지). 위치 추정은 보드 실제 스텝으로 갱신. 이전 펌웨어는 기존 20스텝 방식 유지 |
| PC `tests/test_jc1060_drive.py` | 속도 조그 시험 9개 추가. 기존 시험도 조그 지원 보드 조건에서 다시 실행 |
| JC1060 `ui.cpp`, `pc_link.*`, `ui_text.cpp` | "명령 간격" 슬라이더를 "최대 속도 %"(10~100, 기본 100)로 변경, `speed_pct` 전송. 이전 PC 호환용 `interval_ms`도 함께 전송 |

Y축 역방향 수정과의 관계: 최고 속도는 그대로 500 step/s이며, 가속도도 기존 축 설정(500 step/s²)을 씁니다. 빨라진 이유는 최고 속도를 올린 것이 아니라 정지·재출발을 없앤 것입니다.

- JC1060 `python tools/check_ui_text.py`: 254개 키 통과. 새 한국어 문구의 글자는 기존 글꼴에 모두 있음.

# 추가: 안내 음성 반복 방지와 켜기/끄기 (2026-10-26)

## 원인
JC1060의 단일 스텝·레일·+1/-1 반복 버튼은 PC `/api/drivemcu/command`로 가고, PC는 `b…`/`mz…` 명령이 수락될 때마다 "분류구조 작동합니다."를 새 스레드로 TTS 생성·재생했습니다. 길게 누르거나 연달아 누르면 같은 문장이 줄지어 재생됐습니다. 다른 자동 안내도 중복 제한이 없었습니다.

## 변경
| 위치 | 내용 |
|---|---|
| PC `app.py` | 자동 안내 25곳을 `speak_guidance()`로 통일. 같은 문장이 8초 안에 다시 요청되면 생략(요청이 이어지는 동안 창이 연장됨). 긴급 정지 사이렌은 2초 고정 창. JC1060 하트비트의 `guidance:false`면 JC1060이 음성 보드일 때 안내 생략. `/api/status`의 `jc1060.guidance`에 표시 |
| JC1060 `onboard_audio.*`, `pc_link.cpp` | NVS `jc_audio/guide` 저장·복원, 하트비트에 `guidance` 전송 |
| JC1060 `ui_settings.cpp`, `ui_text.cpp` | 설정 → Sound에 "안내 음성: 켜짐/꺼짐" 버튼 |
| PC `tests/test_guidance_repeat.py` | 반복 생략·문장 독립·스위치·사이렌 창 시험 4개 |

AI 대답과 음성 명령 응답(`tts_to_pcm_and_send` 직접 호출), 긴급 정지 사이렌은 스위치와 관계없이 재생합니다.

## 검증
- `test_guidance_repeat`, `test_jc1060_drive`, `test_board_settings` 77개 중 76개 통과. 실패 1개(`test_templates_render_both_board_modes`)는 시험 환경에 frontend 템플릿을 복사하지 않아서 생긴 것이며 이번 변경과 무관합니다. 사용자 PC에서 `python -m unittest discover tests`로 다시 확인하세요.
- `tools/check_ui_text.py` 258개 키 통과. 새 한국어 글자는 기존 글꼴에 있음.
- 펌웨어 빌드·실물 확인은 하지 않음.

# 추가: 조이스틱 자동 재가동, PID와 무관한 조그 (2026-10-26 오후)
- JC1060 `pc_link.cpp`: 조이스틱·레일 버튼 입력이 있으면 무장되지 않은 상태에서도 입력을 저장하고 drive 태스크가 먼저 `arm`을 보낸 뒤 바로 조그를 보냅니다(E-STOP 후 포함). 거부되면 1초마다 재시도. PID가 켜져 있어도 수동 제어를 해제하지 않음.
- JC1060 `ui.cpp`: PID로 제스처를 중단하지 않음. 상태 문구 "조작하면 바로 이동합니다", PID 켜짐이면 "레일 조작 시 PID 꺼짐".
- DriveMCU `motion.cpp`: PID 중에도 X/Y 조그 허용. Z 조그가 0이 아니면 PID를 끔. PID를 켜면 Z 조그만 정지. 상태에 `program`(이동 큐·귀환 중) 추가.
- PC `jc1060_drive_routes.py`: `program`을 보고하는 펌웨어는 PID·Z 이동과 관계없이 arm·조그 허용, `program`일 때만 대기. 예전 펌웨어는 기존 규칙 유지.
- 시험: `test_jc1060_drive` 전체 통과(새 시험 2개 포함). 빌드·실물 확인은 하지 않음.
