# 기존 DriveMCU의 PC 제어 명령 전송 수정

2026-10-25. 대상은 JC1060 내장 모터가 아닌 기존 DriveMCU이며, PC에서 조작할 때 제어 명령이 누락되는 증상에 대응했다.

## 실제 장치에서 읽은 정보

- 실행 중인 PC 서버 `/api/status`에서 기존 DriveMCU가 Online이었다. 수신 신호 세기는 조회 당시 -27 dBm이었다.
- 기존 DriveMCU TCP 5002의 읽기 전용 `ping`은 약 47ms에 `ACK:PONG`을 반환했다.
- 읽기 전용 `status`는 약 31ms에 protocol 1, busy=false, stopped=false, pid=false를 반환했다.
- 실제 장치로 이동·정지·설정 명령을 보내지 않았다. 이 조회 결과는 현장 제어 누락의 완전한 재현이나 모터 부하 시험 결과가 아니다.

## 확인한 PC 코드 문제

1. 기존 전송 함수는 명령마다 별도 스레드와 TCP 연결을 만들었다. 연속 요청의 전송 순서를 보장하지 않았으며, 펌웨어의 단일 클라이언트 처리 및 작은 연결 대기열과 충돌할 여지가 있었다.
2. `sendall` 직후 연결을 닫아 보드의 `ACK:OK`, `ERR:REJECTED`, `ERR:BUSY`를 읽지 않았다.
3. HTTP 제어 경로는 실제 수락 여부와 무관하게 성공을 반환하고 화면 상태를 먼저 변경했다. IP가 없어 보내지 못한 경우도 성공처럼 표시했다.

## 수정

- `ARD_MAIN/backend/network/drive_transport.py`에 보드 주소별 직렬 명령 전송기를 추가했다. 호출 스레드에서 직접 큐에 넣으며, 다음 명령은 이전 명령의 수락 응답 처리 후 전송한다.
- 큐는 최대 32개로 제한한다. 오래 대기한 일반 명령은 뒤늦게 실행하지 않고 실패로 표시한다.
- 보드 연결을 만들기 전의 연결 실패만 최대 3회 시도한다. 전송이 시작된 뒤 ACK가 없거나 연결이 끊기면 결과를 미확인으로 보고하고 같은 상대 이동을 다시 보내지 않는다.
- 정지 계열 명령은 PC의 대기 명령을 취소한다. 아직 전송하지 않은 이전 연결 재시도도 무효화하며, 기존 ACK 대기로 정지 요청이 오래 지연되지 않도록 한다. 이미 보드에 전달된 동작의 물리 정지 결과는 별도 확인 대상이다.
- 실제 운영 경로인 `backend/app.py`의 드라이브 전송과 `/api/drivemcu/command`를 연결했다. 보드가 수락한 경우에만 해당 수동 요청의 화면 상태와 설정을 갱신한다.
- 거부는 HTTP 409, ACK 미확인은 504, 연결 불가/IP 없음은 503으로 표시한다. 대기 제한을 넘겨 아직 처리 중인 요청은 202로 알린다.
- 화면은 보드 수락, 대기, 거부, 응답 미확인을 구별하고 서버의 오류 내용을 표시한다.
- 기존 DriveMCU는 단말 선택과 독립적으로 기존 IP를 사용하며 JC1060으로 제어 명령을 우회하지 않는다. 음성 정지의 `audio_stop` 구분도 유지했다.
- 분리형 `network/tcp_client.py`의 DriveMCU 전송도 같은 전송기를 사용한다. 다른 보드의 기존 전송 방식은 유지했다.

`ACK:OK`는 펌웨어의 명령 수락을 의미한다. 이동 완료, 실제 기구 위치, 탈조 여부를 증명하지 않는다.

## 검증

- `python -m unittest discover -s ARD_MAIN/tests`: 80개, 종료 코드 0.
- 신규 로컬 TCP 테스트 12개: 20개 연속 명령 순서, 분할 ACK, 명시적 거부, ACK 유실·시간 초과 시 중복 전송 방지, 연결 전 재시도, 큐 포화·만료, 정지 시 대기 취소와 미전송 명령 무효화, 대상 검증, 입력 검증.
- 신규 API 테스트 9개: ACK 후 상태 갱신, 거부·미확인 시 상태 유지, IP 없음·하트비트 IP 대체, JC1060 주소 차단, 선별 작업 중 일반 명령 차단 및 정지 허용, 입력 검증.
- `test_drive_delivery.cjs`, `test_drive_simulation.cjs`, `test_board_dashboard.cjs`, `test_sorting_dashboard.cjs`: 모두 통과.
- 변경 Python 소스 구문 검사와 드라이브 JavaScript 구문 검사 통과.
- 테스트의 TCP 명령은 127.0.0.1의 가짜 보드로만 보냈다.

## 적용 상태

PC 소스 수정과 회귀 검증을 완료했다. DriveMCU 펌웨어는 수정하거나 업로드하지 않았다.

현재 PC 프로그램은 `use_reloader=False`로 실행되므로 소스 수정만으로 실행 중인 프로세스가 바뀌지 않는다. 제어를 마친 뒤 PC 프로그램을 종료하고 기존 `ARD_MAIN/run_pc.bat`으로 다시 실행해야 적용된다. 재시작 전 실제 장치가 움직이거나 작업 중인지 확인해야 한다.

재시작 후 같은 연속 조작에서 `DriveMCU accepted` 또는 구체적인 거부/미확인 메시지를 확인한다. 실제 부하 조건의 모터 동작, Wi-Fi 장애와 장시간 제어는 이번 작업에서 검증하지 않았다.
