# Drive 3D 모델의 전·후진 방향 및 베벨기어 수정

2026-10-25. 사용자가 제공한 화면처럼 트레이가 모터 쪽으로 기울어 겹치는 문제를 메인 프로그램의 3D 표시에서 수정했다.

## 원인

입력 모터와 베벨기어 그룹만 Y축으로 90도 회전해 실제 입력 축은 화면의 월드 Z축이 되었다. 트레이 캐리어는 별도 그룹에서 월드 X축으로 기울고 있어 모터가 있는 전후 방향으로 접혔다. 기존 기어는 떨어진 원뿔대였고, 중심을 관통하는 가로축과 종동 기어도 같은 공간을 차지했다.

## 수정

- 월드 Y=높이, Z=레일·입력 축, X=수거함 방향으로 좌표계를 정리했다.
- 반대 부호 모터 명령의 전도는 공통 입력 축인 Z축에서 이루어진다. 양의 전도는 +X 쪽 상자, 음의 전도는 -X 쪽 상자로 향한다.
- 마주 보는 입력 기어의 시각적 회전 부호를 반영해 캐리어의 기울기와 기어 회전이 같은 축 관계를 따르도록 했다.
- 세 베벨기어를 공통 피치 원뿔 꼭짓점에서 직각으로 만나는 24개 테이퍼 치형으로 구성했다. 입력 축은 각각의 허브에서 끝나도록 나누고, 종동 기어와 출력 스핀들을 연결했다.
- 지지대에 축 구멍을 만들고 트레이 피벗 높이·스핀들 높이·지지대 폭을 조정했다. 트레이의 ±90도 표시 범위에서 지지대와 베이스를 피하도록 배치했다.
- 상자 안쪽 가장자리가 45도 전도 시 트레이의 낮은 배출 가장자리 아래에 오도록 상자 위치를 조정했다.
- 상자 강조는 원형 트레이의 자전각 대신 실제 기울기 부호와 레일 위치를 사용한다.
- 메인 페이지의 3D 스크립트 버전을 `v=7`로 갱신했다.

기어 치형은 3D 표시용이다. 가공용 인벌류트 치형·하중·백래시를 검증한 CAD 설계는 아니다. 물체 낙하의 동역학도 시뮬레이션하지 않는다.

## 검증

- 실제 Three.js r160으로 148개 자세(기울기 -90~90도, 자전 0/90/180/270도)를 검사했다. 트레이 평면과 지지대의 분리, 트레이와 베이스의 간격, 입력/출력 축의 직각 관계, 베벨기어 공통 꼭짓점을 확인했다.
- 앞뒤 레일 위치 ±15mm, 기울기 ±45도, 자전 0/90/270도의 12개 자세에서 트레이 윗면의 낮은 가장자리가 해당 상자의 열린 영역 위에 있는지 검사했다.
- `test_drive_simulation.cjs`, `test_drive_delivery.cjs`, `test_sorting_dashboard.cjs`, `test_board_dashboard.cjs` 통과.
- 보드 선택·템플릿 Python 검사 17개 통과.
- 하드웨어 API를 차단한 독립 HTML에서 실제 Three.js r160/WebGL을 헤드리스 Chrome으로 렌더링했다. 아래 화면은 이 독립 렌더링 결과이며 실제 장치 사진이나 운영 대시보드 캡처가 아니다.
- 실행 중인 서버가 제공하는 `/static/js/simulation-drive.js`와 작업 파일의 SHA-256이 같음을 확인했다.

실물 제어 명령 전송이나 기구 작동 시험은 수행하지 않았다.
