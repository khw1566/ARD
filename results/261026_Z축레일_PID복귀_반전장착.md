# Z축 레일 PID 복귀 · 반전 장착 보정 · 측정/레벨링 도구

## 요약
- DriveMCU 레일 구동을 개루프 스텝에서 ToF PID로 되돌렸다. 기존 PID 코드는 ESP-IDF 포팅본에 그대로 있었고 menuconfig에서 막혀 있었다.
- 레일이 반대쪽에 반전 장착되어 **스텝↔ToF 부호**와 **중앙·배출 위치 거리값**이 원 설계와 다르다. 부호는 새 명령 `mzv`로, 거리는 PC 도구로 실측해 저장한다. 실제 값은 보드에서 측정해야 하므로 추정값은 "미저장(기본값)"으로 표시하고, 선별 시퀀스는 세 위치를 저장하기 전까지 PID 레일을 거부한다.
- 빌드·실기 검증은 하지 않았다(AGENTS.md 빌드 금지). Python·JS 검사만 실행했다.

## 측정·레벨링 순서 (실기)
1. DriveMCU 펌웨어를 빌드·업로드한다.
2. 구동 보드 탭 → **① ToF 안정도**: 정지 상태 표준편차가 1mm 이하인지 확인한다.
3. **② 방향·Steps/mm 자동 측정**: 레일 중간에서 400스텝으로 실행한다. +스텝 이동 → 측정 → 복귀. 방향(`mzv`)과 Steps/mm가 저장·적용된다.
4. **③ 위치 저장**: PID를 끈 상태에서 Z축 버튼이나 조그로 레일을 중앙, +측(금속·종이), -측(플라스틱·유리)에 맞추고 각각 [현재 위치 저장]. +측과 -측이 중앙의 같은 쪽이면 거부한다. [PID 이동]으로 각 위치에 PID로 돌아오는지 확인한다.
5. **④ 반복 정밀도 테스트**: 2~3회 왕복. 위치별 최대 오차, ToF 편차, 스텝 편차(같은 거리에서 모터 위치가 달라짐 = 미끄러짐·백래시), 평균 정착 시간을 확인한다.
6. 선별 시퀀스를 실행한다. 문제가 있으면 "선별 시퀀스 레일 설정"에서 개루프로 되돌릴 수 있다.

## 기본값과 근거
- `rail_dir = -1`: 사용자 설명(반전 장착으로 가감 반대). 자동 측정이 덮어쓴다.
- 중앙 160 / +측 145 / -측 175mm: 기존 HMI·JC1060 PID 범위 145~175의 중앙 ±15mm를 반전한 값. **추정값**이며 티칭 전에는 선별에 쓰지 않는다.
- 폭주 기준 6mm: Python 모델(5샘플 이동평균 지연, 500 steps/s, 가속 1000, ToF 잡음 σ 1~2mm)에서 정상 이동 840회 오작동 0회. 4mm는 17회, 5mm는 4회 오작동. 부호가 틀리면 약 10mm 이동 후 정지.

## 남은 확인 사항
- HMI_MCU(`CONFIG_HMI_RAIL_PID=n`)와 JC1060은 PID 목표를 145~175mm로 제한한다. 실측 위치가 이 범위를 벗어나면 그 화면의 목표 버튼 범위도 바꿔야 한다.
- 3D 모델의 레일 표시는 스텝/Steps/mm로 계산하며 방향 부호는 반영하지 않는다.

## 추가: ToF 배선 진단 (2026-10-26)
- 배선: VL53L0X는 기존 I2C 버스(I2C_NUM_0, **SDA GPIO22 / SCL GPIO23**, 100 kHz, 내부 풀업)를 AHT20(0x38)·BMP280(0x76/0x77)·SSD1306(0x3C)과 함께 쓴다. ToF 주소 0x29는 겹치지 않는다. 기존 PlatformIO 펌웨어와 같은 핀이다.
- 펌웨어 확인: 사용자가 11:22에 빌드한 바이너리는 `CONFIG_ARD_ENABLE_TOF=1`, `CONFIG_ARD_ENABLE_RAIL_PID=1`로 빌드되었다. 코드 경로상 버스·포트·초기화 순서 충돌은 없다.
- 수정(`main/sensors.cpp`): 부팅 시 한 번만 초기화하던 ToF를, 준비되지 않으면 2초마다 다시 시도한다(XSHUT이 늦게 올라가거나 전원이 늦은 경우). 상태를 구분해 로그와 `tof_status`에 보고한다: `NO_DEVICE`(0x29 응답 없음: 배선·전원·XSHUT), `BAD_ID`(0x29에 다른 장치), `INIT_FAIL`(응답 후 설정 실패).
- 하드웨어 확인 항목: VIN/GND 공통 접지, SDA↔SDA·SCL↔SCL(교차 아님), XSHUT을 3.3V에 연결(모듈에 풀업이 없는 경우 대기 상태로 응답하지 않음), 보호 필름 제거.
