# AI기반 자동화 분류장치 — 3분 기술 원리 영상 컷 구성 및 대본

작성일: 2026-10-26

## 제작 기준

- 정식 명칭: **AI기반 자동화 분류장치**
- 기준 CAD: **ARD_Model_v2.iam**. 그리퍼와 3축 로봇은 영상 범위에서 제외한다.
- 주 시청자: 경진대회 심사위원 및 일반 관람객으로 가정. 정식 명칭·제출 규격 확인 후 조정한다.
- 전체 180초. **0:00–2:15 컴퓨터 그래픽 135초 / 2:15–3:00 실제 작동 화면 45초**.
- 기본 화면: 1920×1080, 16:9, 30fps. 총 5,400프레임.
- 전달할 내용: 카메라와 AI의 분류 결과를 차동 기구의 선회·전도와 레일 이동으로 연결하고, 사용자가 화면에서 제어 과정을 확인하는 시스템.
- 구성: 기술적 과제 → 전체 구조 → 차동 기구 원리 → 비전 분류 → 순차 구동·완료 확인 → 실물 시연.
- 내레이션은 사용자의 개인 TTS로 제작한다. 아래 시간은 편집 목표이며 실제 발화 길이는 TTS 출력 후 맞춘다.
- 코드 기반 제작안: Remotion으로 컷·자막·음원·촬영본을 배치하고, React Three Fiber/Three.js로 CAD와 기구 애니메이션을 표현한다.

## 시각 연출

밝은 회백색 배경에 짙은 회색 기구를 배치한다. 판단·정보 흐름은 청록색, 구동부는 주황색으로 강조한다. 부품 전체를 복잡하게 회전시키기보다 설명하는 부품만 색을 주고, 나머지는 반투명하게 처리한다.

분류함의 이름·색·배치는 실제 장치와 맞춘다. 현재 코드는 AI 응답을 Plastic, Metal, Glass, Paper, Others로 구분하지만, 배출 위치는 금속/캔, 유리/기타, 종이/팩, 플라스틱의 네 위치다. 다섯 개 분석 항목을 다섯 개 수거함으로 표현하지 않는다.

자막은 한 번에 핵심 한 문장만 표시한다. 내레이션 전체를 상단 제목으로 반복하지 않고, 전체 발화 자막은 화면 하단에 별도로 둔다. 설명용 단면과 화살표에는 작은 ‘작동 원리 시각화’를 표시한다.

> 이 장치는 비전 카메라의 분석 결과를 분류 기구의 움직임으로 연결합니다. 핵심은 판단 결과를 실제 배출 동작으로 바꾸는 과정입니다.

### C03 / 0:22–0:36

> 비전 카메라가 촬영한 이미지를 피씨에서 분석합니다. 분류 결과는 목표 위치로 바뀌고, 드라이브 엠씨유가 각 모터의 이동 명령을 실행합니다.

### C04 / 0:36–0:51

> 핵심은 트레이 아래의 차동 베벨기어입니다. 두 모터의 입력을 조합해, 트레이의 방향을 바꾸는 선회와 물체를 떨어뜨리는 기울임을 만듭니다.

### C05 / 0:51–1:07

> 두 모터에 같은 부호의 이동 명령을 주면 트레이가 선회합니다. 반대 부호의 명령을 주면 트레이가 기울어집니다. 이 두 움직임으로 배출 방향과 동작을 나눠 제어합니다.

## 실제 시연 편집 규칙

- 위 45초 배분은 실제 한 사이클의 소요 시간을 확인하기 전의 초안이다.
- 시작 조작부터 배출·복귀까지 한 사이클을 먼저 끊지 않고 촬영한다. 화면 녹화도 동시에 시작한다.
- 한 사이클이 30초 이내면 C12에서 가능한 한 연속으로 보여준다. 남는 시간에는 배출부 확대 또는 다른 분류 사례를 넣는다.
- 한 사이클이 30초보다 길면 C11/C13의 여유를 먼저 줄인다. 그래도 길면 분석 대기 구간을 명시적으로 줄이거나 배속하고 ‘분석 대기 구간 축약’, ‘2배속’ 등의 문구를 표시한다.
- 실제 처리 속도를 주장하려면 해당 구간을 정상 속도로 보여주고, 시작·종료 기준이 있는 실측 시간을 사용한다.
- 화면만 완료됐다는 이유로 물체 배출 성공을 표시하지 않는다. 실제 낙하와 복귀가 보이는 컷을 사용한다.
- 그리퍼와 3축 로봇은 사용하지 않는다. 물체를 트레이에 올린 상태에서 비전 분석과 DriveMCU 분류 동작을 보여준다.

## 필요한 자료 — 우선순위 순서

### 1. 최종 기구 확인 자료

- 현재 장치 전체 사진: 정면·측면·사선 각 1장. 카메라와 네 분류함 위치가 보이게 촬영.
- 사용자 지정 최종 조립체: `ARD_Model_v2.iam`. 이 조립체를 기준으로 외형·축·배출 위치를 정한다. 원본 조립체는 이미 있으므로 부품별 내보내기 자료를 추가로 준비한다.
- 영상용 내보내기: 전체 조립체 1개 + 움직이는 부품별 파일. 트레이, 캐리어, 입력축 A/B, 각 기어, 레일 이동부, 고정부를 분리하면 좋다.
- 가능하면 조립 좌표·계층을 유지한 GLB. STL이면 **mm 단위, 공통 조립 원점·방향 유지**, 부품명 표시. 각 부품을 개별 원점으로 자동 중앙 정렬하지 않는다.
- 회전축·회전 중심 표시 그림 1장과 ‘모터 A만 / 모터 B만 / 함께’ 구동한 짧은 확인 영상. 부호와 기구 회전 방향을 맞추는 데 사용.
- 기존 STL은 이미 다수 있으므로 전부 새로 만들 필요는 없다. 최신 조립 상태와 일치하는 파일만 먼저 지정하면 된다.

### 2. 실제 작동 영상과 화면

- 실제 선별 한 사이클 원본: 가능하면 분류 대상 한 종류당 1개, 적어도 성공 사례 1개.
- 권장 촬영: 가로 4K 30fps 또는 1080p 30fps 이상, 삼각대 고정, 초점·노출 고정. 시작·종료 앞뒤에 3초 여유.
- 필수 구도: 전체 장치와 물체·트레이·배출함이 보이는 사선 구도. 보조 구도: 차동 기구 확대, 낙하 지점, 시작 버튼 조작.
- 같은 시연의 PC 화면 녹화. 촬영 이미지, AI 결과, 단계 표시, 3D 화면을 읽을 수 있는 크기로 확보.
- 실제 한 사이클 소요 시간. 촬영·분석·구동 각 구간의 시간을 알면 45초 시연 구성을 정확히 조정할 수 있다.
- 로그인 정보·API 키·개인 네트워크 정보가 녹화 화면에 나오지 않게 정리.

### 3. 개인 TTS 음원

- 먼저 C04 또는 C05를 샘플로 생성. 평소 사용할 속도와 목소리로 전달.
- 최종 음원은 C01부터 C13까지 개별 WAV 파일. 원본 샘플레이트 유지, 무손실 PCM 권장. 파일명 예: `C04.wav`.
- BGM·효과음 없이 목소리만 생성. 문장 사이의 자연스러운 쉼은 유지하고, 파일 앞뒤의 긴 무음은 최소화.
- 각 컷은 끝에 약 1~2초의 화면 여유를 목표로 한다. 음원이 길면 문장을 먼저 줄이고, 과도한 음성 배속은 피한다.
- 개인 TTS가 파일 출력이 가능하면 API 연동 자료는 필요 없다. 자동 재생성을 원할 때만 요청·응답 형식과 비밀값을 제외한 예시를 추가한다.

### 4. 표기·강조 사항

- 정식 프로젝트명은 ‘AI기반 자동화 분류장치’로 확정. 팀명·로고, 제출처와 영상 규격은 추가 확인.
- 확정 강조 요소: 비전 분석 → DriveMCU의 순차 제어 → 차동 기구의 분류 원리. 그리퍼는 제외한다.
- 정량 성과가 있다면 정확도·시험 개수·사이클 시간·허용 하중 등의 실제 측정 기록. 확인된 데이터만 영상에 넣는다.

## 기술 표현의 경계

- 현재 코드를 검토한 구성안이며, 이번 작업에서 빌드·실물 검증은 수행하지 않았다.
- 레일의 자동 선별 이동은 스텝 기반이다. ToF 폐루프 보정이 선별에 사용되는 것으로 설명하지 않는다.
- 완료 위치 확인은 MCU가 보고하는 스텝 상태를 기준으로 한다. 엔코더로 실제 위치를 검증하거나 탈조·물체 낙하까지 검출한다고 표현하지 않는다.
- AI의 분류는 이미지에 대한 추론이다. 재질을 물리적으로 측정하거나 모든 복합재를 정확히 판별한다는 주장을 넣지 않는다.
- 기존 보고서의 ‘완벽 판별’, ‘탈조 원천 차단’, 확정적인 토크 배수·특허 우위 주장은 이 대본에 사용하지 않았다.
- 최신 JC1060 구성에서는 터치·음성 역할과 독립 DriveMCU를 구분한다. 보드 개수를 고정된 핵심 성과로 내세우지 않는다.
- 사용자 승인 경로와 자동 선별 경로를 구분한다. 모든 구동이 항상 수동 승인을 거친다고 설명하지 않는다.
- 대본의 음성은 영상 제작용 개인 TTS다. 장치의 음성 제어 기능과 같은 엔진이라고 가정하지 않는다.
