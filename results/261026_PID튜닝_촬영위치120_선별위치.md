# PID 튜닝과 촬영 위치 분리

## 적용한 설정

| 항목 | ToF 목표 |
| --- | --- |
| 중앙 기준 | 95 mm |
| 금속·종이 | 70 mm |
| 플라스틱·유리 | 120 mm |
| 촬영·시작·완료 복귀 | 120 mm |

`ARD_MAIN/backend/rail_calibration.json`에 반영했다. 기존 실측 방향 -1, Steps/mm 23.683과 티칭 상태를 유지했다. 신규 기본값도 같은 거리로 맞췄다. PC 프로그램이 이미 실행 중이면 재시작해야 파일 값을 다시 읽는다. 부팅 시 자동으로 모터를 움직이지 않는다. 선별 시작을 누르면 촬영 위치로 이동한다.

선별 시작 → 120 mm PID 이동 → 정착 확인 → PID 끄기 → 새 프레임 촬영 → 분석 → 분류별 70/120 mm 이동 → 선회·배출·수평 복귀 → 120 mm 복귀. 중앙 95 mm는 측정 도구의 기준 위치로 유지한다. 촬영 위치 정착에 실패하면 촬영/배출하지 않는다. 기존 개루프 모드를 선택하면 거리 PID 촬영 위치 정렬은 수행하지 않는다.

## PID 수정

- 초기값: P=0.12, I=0, D=0. 펌웨어 기본값과 PC 저장값을 일치시켰다. 실물 응답으로 튜닝한 확정값은 아니다.
- 같은 ToF 측정 프레임으로 적분·미분을 반복하지 않는다. 새로운 프레임 간 시간으로 계산한다.
- 목표 ±1.5 mm에 들어오면 보정 정지 상태로 들어간다. ±2 mm를 벗어난 새 프레임이 2회 연속 나올 때만 재보정한다. `rail_settled`는 기존처럼 ±2 mm 안에 있고 Z가 멈췄을 때만 true다.
- 목표 8 mm 이내에서는 짧은 보정이 끝난 뒤 120 ms 기다려 센서 필터가 정지 위치를 반영하게 한다.
- 보정 명령은 최대 2 mm, 남은 오차의 최대 25%로 제한한다(최소 제한폭 1 step). 출력 포화 시 적분을 비우고 미분을 평활화한다. 기존 D의 0.01 배율을 유지한다.
- 목표 변경/센서 오류/계수 변경 후 과거 오차로 미분항이 튀지 않도록 상태를 초기화한다.

## PC 조작

구동 보드 탭의 Z축 Rail PID 카드에서 다음을 제공한다.

- 보드 현재 P·I·D와 PID ON/OFF 표시. 입력란은 저장값/수정 초안이며 실제 보드값과 구분한다.
- `초기값 0.12 / 0 / 0 입력` 버튼.
- `P·I·D 적용 및 PC 저장` 버튼. PID OFF·모터 정지 상태에서 3개 계수를 전송하고 ACK 및 실제값 재조회를 확인한 뒤 PC 파일에 저장한다. 실패를 성공으로 표시하지 않는다.
- 보드 현재값을 보고하지 않는 구 펌웨어에서는 적용을 막고 업데이트 필요를 표시한다.
- 계수는 PC JSON에 저장된다. 펌웨어에서 NVS에 저장하지 않으므로 재부팅 후 수동 적용하거나 선별 시퀀스 시작 시 저장값이 적용된다.
- 선별 시퀀스 레일 설정의 `촬영·시작 위치 (mm)`에서 촬영 위치를 별도로 변경할 수 있다.

## 검증 범위

- Python 레일/튜닝/촬영 순서 테스트 22개 통과. 보드 가상 응답을 사용한다.
- Python 선별 파이프라인 테스트 13개 통과.
- 보드 라이브 상태·계수 전파 테스트 6개 통과.
- Node PID UI 테스트: 실제 JS 핸들러를 모의 DOM/HTTP에서 실행해 현재값 표시, 입력 중 무전송, 적용, PID 활성 중 차단, 적용 실패 처리 확인.
- Node 선별 대시보드 회귀 검사와 변경 JS 구문 검사 통과.
- 변경 Python 5개 파일 AST 구문 검사 통과.
- 에이전트는 펌웨어/앱 빌드, 플래시, 모터 이동, 실물 PID 응답 검증을 수행하지 않았다. 오버슛 감소 효과는 실물 확인이 필요하다.
