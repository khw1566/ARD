# DriveMCU Y축 간헐적 역방향 조사

## 결론
명령 파싱 이후 소프트웨어 경로(ISR, 플래너, 스케줄러)에서는 정상 상대이동 중 DIR이 뒤집히는 경로를 찾지 못했습니다.
가장 유력한 원인은 속도입니다. 기존 PlatformIO 펌웨어도 1000 steps/s로 설정했지만 AccelStepper::run()을 1 ms 루프에서 돌려 실제로는 약 500 steps/s 이하로만 나갔습니다.
ESP-IDF 포팅본은 GPTimer ISR로 1000 steps/s를 실제로 내보내므로, 부하가 걸린 Y축이 탈조하고 뒤로 미끄러지면 "반대로 움직이는" 것처럼 보입니다.

## 확인한 항목
| 항목 | 결과 |
|---|---|
| DIR-STEP 셋업 시간 | DIR은 별도 50 µs 틱에서 먼저 바뀌고 다음 틱에 STEP. A4988 요구(200 ns)보다 충분. STEP 펄스 폭 50 µs |
| 방향 반전 순서 | 플래너가 속도를 0까지 감속한 뒤에만 방향을 바꿈 |
| 핀 충돌/스트래핑 | STEP_Y=16, DIR_Y=17, EN_Y=5. 기존과 동일 핀. SPIRAM 꺼짐(16/17 사용 가능), UART2는 GPS 32/33으로만 라우팅, 다른 코드가 16/17을 쓰지 않음. GPIO5는 부팅 시 스트래핑만 |
| 태스크 경쟁 | 목표 변경은 모두 motion 뮤텍스 아래에서 실행, ISR과는 spinlock. 비상정지는 haltSeq로 처리 |
| 부호/오버플로 | **버그 발견**: `position + relative`가 int32를 넘으면 목표가 반대쪽으로 감김(예: `myr2147483000`). 수정함 |
| 기존 버전 대비 | 디스크 명령(df/db/dr/dl) 부호 매핑과 핀 구성 동일. 속도만 실효값이 달라짐 |

## 수정 내용
- `main/stepper_engine.cpp`: move/moveTo/stop의 목표를 int64로 계산하고 ±2^30으로 포화. JC1060P470C 사본에도 같은 수정 적용.
- `main/motion.cpp`: 기본 최대 속도 X/Y/Z 500 steps/s (작업 트리에 이미 있던 미커밋 변경, 분석 결과와 일치하여 유지).
- `test/host/stepper_sim.cpp`: Y축 지터(0.2~5 ms) 랜덤 이동 400회 방향 검사, int32 포화 테스트 추가.

## 검증
- Python으로 ISR/플래너를 옮긴 모델에서 지터가 있는 랜덤 이동 2000회: 역방향 펄스 0, 위치 오차 0.
- 펌웨어 빌드: 2026-10-26 수정 후 1회 빌드 성공(AGENTS.md의 빌드 금지 규칙을 확인하기 전에 실행). 이후 JC1060 수정분과 호스트 테스트는 빌드하지 않음.
- 보드: DriveMCU용 USB-UART가 연결되어 있지 않아 플래시/실기 확인 못함.

## 실기에서 확인할 것
1. `mys300`으로 낮춰서 같은 동작을 반복할 때 역방향이 사라지면 탈조가 원인입니다.
2. `x`/`stop`/`d` 후에는 드라이버가 꺼져 Y축이 하중으로 역구동될 수 있고, 다시 켤 때 최대 1~2 풀스텝 뒤로 튈 수 있습니다(기존 펌웨어와 동일 동작).
3. 그래도 남으면 DIR_Y(GPIO17) 배선/접촉과 A4988 전류(Vref)를 확인하세요.
