# 메인 대시보드 이미지 분석 및 기구 작동 수정 보고서
## 1. 기존 문제
기존 구현에는 이미지 분석 호출과 모터 명령 전송이 존재했지만, 전체 선별 과정의 성공 여부를 확인하는 연결이 부족했다.
- 촬영 명령은 현재 ImageSenderMCU에서 비활성화된 TCP 5003 경로를 사용했다.
- 새 이미지 여부를 파일 길이로 비교하여 동일 길이의 새 JPEG를 놓칠 수 있었다. 수신 실패 시 이전 이미지로 진행했고, 카메라 오프라인 상태에서도 캐시를 허용했다.
- 분석 실패를 Others로 대체하여 잘못된 배출을 실행할 수 있었다.
- 모터 명령을 비동기로 보내고 고정 지연 뒤 다음 단계로 진행했다. 명령 수락, 이동 완료, 재부팅과 정지를 확인하지 않았다.
- 레일 변환에 1000스텝/30mm 가정을 사용하여 실제 DriveMCU Steps/mm 설정과 달랐다.
- UI는 목표 각도를 현재 자세처럼 표시했다. 중복 시작 경쟁 및 변경 가능한 상태 객체를 그대로 SSE 큐에 넣는 문제도 있었다.

## 2. 구현한 실제 순서
- 양쪽 MCU 온라인 상태, 감속비, DriveMCU 상태 조회 지원 여부를 검사하고 작업을 한 번만 예약한다.
- X/Y 논리 원점, 모터 대기 상태, 레일 PID 해제를 확인한다.
- ImageSenderMCU가 실제 사용하는 설정 폴링 채널에 capture를 등록한다.
- 요청 이후 수신한 새 이미지 프레임을 기다린다. 크기가 같아도 새 수신으로 인정하며, 시간 초과 시 이전 이미지를 대신 사용하지 않는다.
- 해당 이미지에 설정된 Gemini 모델을 호출하고 물체명 및 다섯 재질 중 하나인지 검증한다. 실패하면 모터를 움직이지 않는다.
- 재질별 레일 이동 → Yaw 선회 → Roll 45도 전도 → 낙하 대기 2초 → 수평 복귀 → 선회 복귀 → 레일 시작 위치 복귀를 순차 실행한다.
- 각 이동은 ACK와 MCU busy 해제, X/Y/Z 완료 스텝을 확인한다. 작업 도중 boot_id 변경, 정지, PID 전환, 목표 스텝 불일치, 통신 실패 또는 시간 초과는 오류로 처리한다. 이동 이후 오류 발생 시 x 정지를 시도한다.
- 시작 위치 복귀까지 확인한 경우에만 완료로 표시한다. 진행 중 별도 대시보드 모터 명령과 카메라 제어는 차단하며 중단은 허용한다.

## 3. 사용자 지정: ToF 없는 개루프 제어
사용자의 지시에 따라 선별 시작, 레일 이동 및 완료 판단에서 ToF를 사용하지 않는다. 고장 센서의 0mm 값으로도 개루프 선별을 실행할 수 있다.
레일은 시작 위치를 분류 중앙 0mm로 간주하고 ±15mm만큼 상대 이동한다. 이동 스텝은 round(이동 mm × DriveMCU의 Steps/mm)이다. 기본 43.48이면 15mm는 652스텝이며, 복귀는 실행한 스텝의 정확한 음수로 수행하여 시작 카운터로 돌아간다.
- Metal: Yaw 90도, 레일 +15mm
- Glass / Others: Yaw 90도, 레일 -15mm
- Paper: Yaw 270도, 레일 +15mm
- Plastic: Yaw 270도, 레일 -15mm
이는 기존 웹 수거함 배치를 유지한 매핑이다. 실제 수거함 배치, Z 방향 및 감속비는 기구에서 확인해야 한다.
개루프이므로 시작 전 실제 트레이 수평 및 레일 중앙 정렬이 필요하다. X/Y 카운터가 0이라는 것은 물리 원점 센서 확인을 뜻하지 않는다. 재부팅 직후 카운터 0도 실제 위치를 보장하지 않는다. 스텝 완료는 펄스 실행 완료이며 탈조, 기구 걸림, 실제 물체 낙하 성공은 확인할 수 없다.
기존 home은 X/Y 복귀 명령과 레일 PID 목표 설정을 포함한다. PID가 꺼져 있으면 이 명령으로 레일이 중앙에 복귀했다고 간주하지 않으며, 자동 선별 복귀는 home을 사용하지 않고 역스텝으로 처리한다.

## 4. 수정 파일 및 역할
- pc_center/backend/core/sorting_pipeline.py: 새 이미지 수신 동기화, 분석 검증, 통신 응답 및 스텝 완료 확인, 개루프 선별 상태 머신.
- pc_center/backend/app.py: 폴링 촬영, 실제 AI 분석, 선별 시작/중단 API, 수신 이미지 연결, SSE 상태 복사 및 별도 제어 차단.
- DriveMCU/src/main.cpp: TCP status 프로토콜 1 추가. boot_id, busy, stopped, pid, X/Y/Z 스텝, Steps/mm, 진단용 ToF를 제공한다. 이동 큐에서 Z축 완료도 확인하도록 수정했다.
- pc_center/frontend/static/js/main.js: 완료 확인 단계의 자세 표시, 오류 상태, 작업 중 중단 버튼, 새로고침 시 상태 복원.
- pc_center/frontend/static/js/simulation-drive.js: 선별 레일 좌표를 시작 위치 기준 상대 mm로 해석.
- pc_center/frontend/templates/index.html: 실제 단계 명칭 및 개루프 준비 안내, 스크립트 캐시 갱신.
- pc_center/tests/test_sorting_pipeline.py / test_sorting_integration.py / test_sorting_dashboard.cjs: 정상 분류, 실패 차단, 재부팅, 중단, 이미지 수신 및 UI 회귀 검증.

## 5. 검증과 적용
Python 회귀 테스트 20개, JavaScript 문법 및 3D/대시보드 회귀 검사가 통과했다. DriveMCU PlatformIO 빌드가 성공했다. 실제 Gemini 요청, 네트워크 MCU 통신 및 실물 선별 시험은 이 작업에서 수행하지 않았다.
DriveMCU의 새 status 응답이 필요하므로 수정 펌웨어를 업로드해야 한다. 이전 펌웨어가 연결되면 선별은 오류 안내 후 중단한다. PC 서버도 재시작하고 웹 페이지를 새로고침해야 한다.
ImageSenderMCU는 현재 설정 폴링 촬영 기능을 사용하므로 이 선별 변경만을 위해 추가 펌웨어 수정은 필요하지 않다.

## 6. 남은 관측 한계
새 이미지 판별은 수신 순번 기준이다. 프레임에 촬영 요청 ID가 없으므로 다른 장치가 이미 전송 중이던 프레임과 요청별 상관관계까지 보장하지는 않는다.
웹의 각도는 모터 스텝과 설정 감속비로 산출하며 엔코더 실측값이 아니다. 낙하 대기 2초는 완료 센서가 없는 배출 과정의 대기 시간이다. MCU 통신이 끊긴 경우 정지 전달도 실패할 수 있으며 UI는 이를 선별 성공으로 표시하지 않는다.
