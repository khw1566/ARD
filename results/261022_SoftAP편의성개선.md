# 저장소 확인 및 소스 복원

- 원격: `https://github.com/khw1566/ARD`, ESP-IDF 브랜치: `ard-v1`.
- 확인한 커밋: `871f7765c52c63030560217e86b444dc1999c6f0`.
- 원격에는 ESP-IDF 5개 프로젝트의 네트워크 및 HMI 소스가 모두 있었습니다.
- 이 노트북은 Git 루트 트리와 인덱스가 누락된 상태였습니다. 원격에서 별도 확인한 Git 데이터를 이용해 메타데이터를 복구했습니다.
- ESP-IDF 기존 파일 68개는 원격과 일치했습니다. 누락 파일 150개를 원격에서 복원했습니다. 복원 중 기존 파일은 덮어쓰지 않았습니다.
- 원격 저장소에는 변경 내용을 올리지 않았습니다. ESP-IDF 이외의 작업 폴더 누락 파일은 이번 복원 범위에 포함하지 않았습니다.

# 구현

- ESP-IDF 5개 프로젝트에 공통 스캔·성공 기록·QR 모듈을 연결했습니다.
- 시리얼에 SoftAP 접속용 QR과 웹 설정 주소 QR을 표시합니다.
- HMI_MCU와 JC1060P470C 화면에서 QR을 볼 수 있습니다.
- 웹 화면 자동 SSID 검색, 재검색, 저장된 비밀번호 채우기 및 비밀번호 표시를 추가했습니다.
- 성공 기록 16개를 NVS에 보관합니다. DHCP 성공 후 갱신하며 가장 오래된 성공 기록부터 교체합니다.
- 자동 연결은 주변 검색 결과와 일치하는 저장 SSID에만 시도합니다. 실패 시 검색되지 않은 SSID를 순회하지 않습니다.

# 검증 결과

- `node ARD_ESP-IDF/shared/test/test_portal.js`: 통과. 자동 검색, 대기, SSID의 안전한 텍스트 표시, 비밀번호 선택, 공개 AP, 오류 후 재검색을 확인했습니다.
- `git diff --check -- ARD_ESP-IDF`: 통과.
- `git fsck --connectivity-only --no-reflogs`: 종료 코드 0. 원격 데이터 재수신 후 누락되거나 연결이 끊어진 Git 객체가 없음을 확인했습니다.
- 소스 통합 검사: 5개 프로젝트의 CMake 소스 경로, 공통 웹 페이지 경로, 검색 API와 비밀번호 치환, 공통 연결 관리 호출을 확인했습니다.
- ESP-IDF 사전 점검: 설치 SDK 5.5.5, 대상 ESP32-P4, LVGL 기록 9.2.2. 복원 후 필요한 프로젝트 소스가 존재함을 확인했습니다. 현재 빌드 캐시와 컴파일 데이터베이스는 없습니다.
- `python ARD_ESP-IDF/shared/test/run_tests.py`: 실행 시도했으나 로컬 Visual Studio의 표준 C 헤더 누락으로 컴파일 중단. 첫 진단은 `assert.h`를 찾을 수 없다는 C1083 오류입니다. 테스트 통과로 간주하지 않습니다.
- 펌웨어 빌드·링크, 새 화면 렌더링, 보드 업로드 및 실물 QR 스캔·Wi-Fi 동작은 검증하지 않았습니다.

사용 방법과 파일 목록은 `ARD_ESP-IDF/shared/README.md`를 참고하세요.
