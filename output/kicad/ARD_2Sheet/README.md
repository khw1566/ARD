# ARD 실제 KiCad 회로도 - 2장

`ARD_2Sheet.kicad_pro`를 KiCad 10에서 연다. 루트 `ARD_2Sheet.kicad_sch`가 첫 장이며, 계층 시트 심볼을 열면 두 번째 장이다. 심볼·핀·배선·넷 라벨을 편집할 수 있는 네이티브 KiCad 파일이다.

- **1장 / A3:** 12V 입력, DC-DC 스텝다운, DriveMCU, A4988 3축 인터페이스, 센서/OLED/GPS/부저, ImageSenderMCU, DVP 카메라.
- **2장 / A3:** JC1060 P4/C6, 내장 디스플레이·터치·오디오 인터페이스, 별도 외부 전원·제작사 배터리 모듈, Robot3Axis 드라이버·릴레이·L298N, 기존 Control/HMI 선택 구성.
- `ARD_2Sheet_회로도.pdf`는 **KiCad CLI가 이 회로도에서 직접 출력한 최종 2쪽 PDF**다. 앞서 만든 구성도 문서와 다르다.
- `ARD2.kicad_sym`, `sym-lib-table`을 함께 보관한다. 모든 심볼은 회로도 파일에도 내장되어 있다.
- `generate_kicad.py`: 재생성 소스. `check_netlist.py`: KiCad 넷리스트를 원본 신호 쌍 및 전원 연결과 비교한다.

## 회로 표현

기존 KiCad 7장과 같은 **보드·모듈 연결 회로도**이다. 모든 논리 포트를 passive로 표현했다. 핀 번호는 GPIO/기능 식별자이며 실제 헤더 핀 번호가 아니다. 동일 시트의 동일 이름 라벨은 전기적으로 연결된다. 네트워크 통신을 전선으로 연결하지 않았다.

12V를 5V로 낮춰 DriveMCU·센서 모듈·ImageSenderMCU에 공급하는 사용자 설명을 반영했다. 공급과 귀환선을 모두 표현했다. 스텝다운 입력/출력 귀환은 비절연 스텝다운의 공통 귀환으로 표현했으며 실제 모듈 접지 구조·정격은 별도 확인 대상이다. 모터 VMOT나 A4988 VDD를 12V 또는 5V로 임의 확정하지 않았다.

XH60은 단자이므로 생략했다. JC1060 외부 전원과 제작사 배터리 모듈은 Drive 5V와 분리했다. JC 전원·배터리 포트는 기능적 연결만 표시했으며 실제 커넥터 이름, 전압, 핀 순서, 충전 회로는 TBD이다. JC1060 내장 오디오는 ES8311 인터페이스까지 표시했다.

두 장에 수록하기 위해 구형 ControlMCU의 조작부·MAX98357A 및 HMI의 LCD·터치는 기능 어셈블리 심볼로 묶었다. 각 GPIO 넷은 보존했다. IC 내부, 센서 IC의 직접 VDD, 모터 코일 단자별 회로, 배터리 충전기 내부 회로는 새로 추정하지 않았다.

## 확인 결과 및 한계

- KiCad CLI 10.0.3에서 두 시트 로드, PDF 및 XML 넷리스트 출력.
- 원본 78개 신호 연결 중 현재 소스에서 미사용인 Drive SW1/SW2/POT 3개를 제외한 **75개 연결**을 KiCad 출력 넷리스트와 비교.
- 12V→5V 출력이 Drive/센서/ImageSender로 연결되고 JC 전원과 합쳐지지 않는지 넷리스트에서 확인.
- ERC: **오류 0 / 경고 26**. 26개 모두 실물 확인이 필요한 TBD 단자가 한 핀 라벨에만 연결되어 있다는 경고이며 숨기지 않았다. 세부 내역은 `erc.rpt` 참조.
- passive 모듈 심볼 ERC는 GPIO 전기 적합성, 전원 안전성, 전압·전류·부품 정격을 검사하지 못한다. 이는 자료 일관성 확인이며 제조사 데이터시트에 근거한 전기적 검증이 아니다.
- 전원 정격, 센서 모듈 5V 입력 적합성·I2C 풀업 전압, 접지·보호회로, JC 배터리 모듈 사양, 실제 단자 순서는 실물 확인 대상이다.
- 펌웨어·시뮬레이터·앱 빌드, PCB 제작 검증, 실물 측정은 수행하지 않았다.

이전 7장 원본은 변경하지 않았다. 이전에 작성한 `output/pdf/ard_system_2p` 구성 문서는 이번 네이티브 회로도의 대체물이 아니다.
